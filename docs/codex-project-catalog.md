# Codex 已有项目列表

更新：2026-10-19。本功能只读取项目元数据并让用户点选，不创建项目、不修改目标状态文件或数据库。

## 交互与授权

1. 打开「在其他 App 继续」不读取项目列表。
2. 点击 Codex 卡片后，在当前面板列出目标已保存的本地项目名称与目录；列表可刷新，超过 5 项时可按名称或路径搜索。
3. 点击可用项目即复核该项目仍存在于当前列表，然后获取绑定来源的短期令牌，进入既有接续事务。不再打开目录选择器。
4. 「独立会话继续」保留；「选择其他文件夹」是系统目录选择器备用入口。加载中、空列表、格式不支持或读取失败不阻断这两个入口。
5. 列表完成或选择完成时再次校验来源授权和当前请求，迟到结果不覆盖新会话或创建旧会话。

固定状态文件的已支持顶层投影：

```ts
{
  'local-projects': Record<string, {
    id: string
    name: string
    rootPaths: string[]
    createdAt: number
    updatedAt: number
```

## 读取边界

- 数据根与接续目标相同：已保存目标位置优先，其次当前进程 CODEX_HOME，最后标准默认位置。每次列表查询重新核验系统关联应用身份，不猜测另一份数据根。
- 只打开该根下固定 `.codex-global-state.json`，不枚举客户端目录，不打开 auth.json、config.toml、会话日志或项目文件。共享状态文件最多 16 MiB，只返回白名单项目字段；不展示、记录或持久化其他字段及 JSON 解析错误片段。
- 检查实际数据根、普通文件、文件句柄身份，拒绝链接；读取有界，交付前复核大小、mtime、ctime、dev/ino 和根身份。变化时报错，不拼接不同快照。
- 最多 1000 项，每项最多 64 个根；超预算或畸形结构不当作空列表成功。状态文件缺失、可读空列表和错误分别处理。
- 列表不遍历各项目目录。实际点选后才检查所选目录的存在性与身份，沿用原有目录令牌、预演、备份、去重、回滚门禁。

## 项目归属的限制

现有事务设置并回读确认的是 `session_meta.cwd`，**没有写入原生项目成员关系**。桌面可根据目录做归属回退，但多个项目共用目录时存在优先规则，不能保证“点哪个就归入哪个”。

因此远程项目不混入本地列表；多根、空根、非本机路径和可识别的共享目录项目保留名称与限制说明，不提供误导性的直接接续。目录唯一的本地单根项目允许按主目录接续。原生 `projectId` 指派、远程项目、完整多根环境迁移和真实 GUI 分组仍未验收，不以 cwd 回读成功冒充成员关系写入成功。

## IPC

- `listCodexProjects(id)`：来源 opaque ID；主进程返回元数据与临时列表 UUID，不暴露原项目 ID 作为写权限。
- `chooseCodexProject(id, projectId?)`：带列表 UUID 时复核同一来源、5 分钟有效期、当前数据根以及项目仍存在且路径未变；不带 ID 才打开文件选择器。未知 ID 或任意路径拒绝，不静默回退。
- 选择成功后仍通过 `continueInCodex(id, {kind:'project',token})` 接续。列表本身不能创建会话。
