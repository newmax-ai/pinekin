# 架构与能力边界

## 分层

| 层 | 路径 | 职责 |
| --- | --- | --- |
| 桌面主进程 | `src/main/index.ts` | 窗口、受限 IPC、原生选择框、剪贴板、协议入口 |
| 本地档案服务 | `src/main/library.ts` | 导入队列、持久化、损坏保护、演示数据组合 |
| 安全桥 | `src/preload/index.ts` | 只暴露具名能力，不暴露任意 IPC、文件路径读写、Node.js |
| 会话核心 | `src/core/` | 统一模型、校验、搜索、交接文本、深链、适配器能力 |
| 界面 | `src/renderer/` | 列表、过滤、详情、交接预览、结果与错误反馈 |

界面无 Node.js 权限，开启 `contextIsolation` 与 `sandbox`。主进程校验 IPC 的发送者和顶层 frame，拒绝窗口导航、新窗口和权限请求。导入内容以 React 文本节点展示，不解析为 HTML，也不执行历史工具调用。

内部桥统一使用 `window.staithe`、`StaitheAPI` 与 `staithe:*` IPC，不向历史包暴露可执行能力。

## 统一会话 v1

```json
{
  "format": "staithe.session",
  "version": 1,
  "session": {
    "id": "example-id",
    "title": "一段值得继续的思考",
    "source": "other",
    "updatedAt": "2026-10-16T00:00:00.000Z",
    "tags": ["思考"],
    "messages": [{ "role": "user", "content": "接下来做什么？" }],
    "demo": false
  }
}
```

这是文本档案格式，不是任意客户端原生数据格式。当前严格拒绝未知字段和未知版本，防止无声丢弃不支持的状态。后续增加附件、分支和工具元数据必须引入新 schema 版本及迁移策略，而不是硬塞进正文。

更名兼容：导入同时接受 `staithe.session` 与旧 `ember.session`，两者都严格使用相同的 v1 schema。导出仅使用新格式 `.staithe.json`；旧版 Ember 无法读取新格式。不会替换用户消息正文中的旧名称。

导入分配新的本地 UUID，避免覆盖已有档案。当前不做语义去重；重复导入会生成独立副本。来源字段只是声明，并不构成可验证的来源证明。

## 三种能力不能混为一谈

1. **档案导入**：能阅读和保存文本，不代表可继续执行。
2. **上下文交接**：把原文与角色交给目标工具，让其在新会话理解历史。没有自动摘要，不冒充目标工具的原生恢复。
3. **原生接续**：涉及会话 ID、工作区、工具状态、权限、模型、客户端版本和官方恢复入口。未逐项验证前不可声明支持。

`SessionAdapter` 的 `readLocal`、`importArchive`、`nativeResume`、`deepLink` 当前对所有外部客户端都为 `false`。Staithe 自己的包导入与本地定位不等于外部客户端的这些能力。

## 深链

新协议：`newmax-staithe://session/<本地ID>`。旧协议 `newmax-ember://session/<本地ID>` 保留为兼容入口，两者走相同的解析与分发逻辑。

- 原始字符串严格匹配；不接受查询参数、片段、用户信息、端口或额外路径。
- 只定位本机档案，不从链接取文件、不联网、不传入 prompt、不触发工具执行。
- 找不到 ID 时明确提示先导入，不伪造空会话。
- 开发模式不注册系统协议；打包应用配置两种协议声明并注册。
- 测试覆盖冷启动参数、应用内事件及消息桥，不等于已完成安装后的系统级协议注册验收。
- ID 在导入时重新分配，因此跨设备交接必须使用会话包，不能复用旧设备深链。
- 更名不会重写已有 ID，演示会话的 `demo-ember` ID 也保留。

## 持久化

`userData/library.json` 是当前最小可运行实现。导入串行化，写临时文件后 `rename`。读取发现损坏即报错，不覆盖旧档案。

产品显示名与存储身份分离：`app.setName('Staithe')`，但默认 `userData` 固定为系统 `appData` 下的旧包名 `@newmax-ai/ember`。无需迁移、复制或重写已有档案。开发模式优先使用 `STAITHE_DATA_DIR`，未设置时接受旧 `EMBER_DATA_DIR`；打包模式忽略两者。测试始终使用临时隔离目录。

此实现尚无数据库索引、备份轮换、整库容量限制、加密、删除或归档操作，适用于原型阶段。真实客户端接入前应增加增量索引与容量策略；大规模档案需要迁移至 SQLite 等可查询存储。

## 验证边界

- 单元：schema、搜索、交接文本、新旧包与深链兼容、能力标记。
- 集成：真实临时目录中的存储读写、并发导入、损坏保护。
- 组件：加载、筛选、空态、导入、导出、复制、错误反馈、深链定位。
- 桌面 E2E：真实 Electron + preload + IPC + 文件服务，原生选择框返回值受控，剪贴板被替换，避免影响用户数据；旧默认目录兼容使用伪造 `appData` 与档案夹具验证。
- 覆盖率阈值 80%：`src/core/session.ts`、`src/main/library.ts`、`src/renderer/src/App.tsx`。数据样例、类型声明、启动入口、preload 和主进程事件编排不计入数值覆盖率，后者通过桌面 E2E 验证主要路径；不是全仓 80% 的声明。
