# Staithe 接入实现建议

日期：2026-10-16。状态：研究建议，尚未实施；不代表已验证任何外部客户端适配。

## 1. 产品边界与结论

建议把 Staithe 定位为**本地优先、跨厂商的会话档案与可解释交接中心**，而不是承诺把任意对话无损写入任意客户端。

四类动作必须分别建模、分别验收：

1. **归档**：保存与检索历史，保留来源及缺失项。
2. **交接**：把用户选定的历史、附件引用和下一步意图，送入一个新的目标会话。
3. **打开来源**：定位原客户端已有会话；不代表内容被迁移。
4. **原生恢复／迁移**：恢复目标运行时认可的会话状态；只有明确版本、工作区和官方入口均验证后才启用。

供应商已经提供某些原生导入，不意味着所有产品都不能迁移；但也不意味着可以生成通用原生包。应维护“来源 × 目标 × 产品版本 × 平台”的支持矩阵。

本方案的竞争差异不是再造一个聊天客户端，而是：统一搜索、原始证据保留、离线归档、敏感内容预览、交接谱系，以及可解释的迁移损失。

## 2. 现有代码的主要缺口

以下是对当前工作区代码的直接观察，不是外部调研结论。

| 位置 | 现状 | 下一步 |
| --- | --- | --- |
| `src/core/types.ts` | `Source` 仅四个枚举；`Message` 只有角色和字符串；没有消息 ID、分支、附件、工具调用关联 | v2 保留结构化事件与来源产品/运行时身份；兼容读取 v1 |
| `src/core/types.ts` | `SessionAdapter` 仅四个布尔能力和一次性 `read()` | 引入版本化能力声明、预览、分批读取、取消、增量游标及损失报告 |
| `src/core/session.ts` | 严格 v1 schema；单包 5 MB；导入只接受自己的两种格式 | 外部格式先通过独立 parser，再规范化；不要为新来源直接放松既有包校验 |
| `src/core/session.ts` | 搜索拼接所有正文；交接包含全部历史 | 改为索引检索、选择范围、预算预览与可追溯摘要 |
| `src/main/library.ts` | 整个 `library.json` 读入内存；每次导入重写全库并分配新 UUID | SQLite 索引、批量事务、幂等导入与内容寻址原件 |
| `src/core/session.ts` | 本地深链只携带 ID | 继续作为本机定位；跨设备必须另有包或经授权的传输渠道 |

不因本次调研直接改这些接口，也不把新格式硬塞进旧 `messages[].content` 后宣称无损。

## 3. 数据分成三层

### 3.1 原件层

保存用户明确选择的导出包、会话日志或读取快照，并记录 SHA-256、大小、来源、取得时间、适配器版本。原件本身也可能包含敏感内容：本地保存须告知，不能默认为分享材料；支持彻底删除和引用计数清理。

外部 SQLite 不直接写入。确有只读接入需求时，需要一致性快照方案：不能只复制主库而忽略 WAL，也不能让 Staithe 隐式创建、迁移或修复源库。加密库、未知 schema 或一致性不能证明时，要求官方导出或暂不支持。

### 3.2 规范化层

建议核心实体：

- `SourceInstance`：产品、地区版、平台、版本、授权范围及证据等级。
- `Conversation`：Staithe ID、原始 ID、标题、时间、工作区提示与来源引用。
- `Message` / `Event`：稳定 ID、父节点、角色、顺序、时间和结构化内容块。
- `ContentBlock`：文本、图片/文件引用、工具调用、工具结果、引用、未知块。
- `Attachment`：内容散列、声明类型、实际类型、大小、缺失原因；引用不自动下载。
- `Branch` / `AgentRelation`：分支、父子会话及协作关系，不把并行消息随意串成一条。
- `ImportRun`：输入散列、游标、警告、错误、完整度和去重统计。
- `Handoff`：来源范围、目标、生成策略、用户编辑和新会话关联。

`productId`、`harnessId`、`modelId` 必须区分：例如 Cindy 是产品，Claude Code/Codex 可以是它内部的运行时。外部模型名不证明原生恢复兼容。

未知块保留原始引用并标记不支持；缺失时间保持缺失，不能用导入时间冒充原始时间。去重键需要产品与账户/工作区命名空间，不可仅用正文哈希合并不同会话。

### 3.3 交接层

默认由用户选择完整记录、选中分支或片段。生成的交接材料区分：

- 用户当前目标与明确的下一步；
- 历史原文、关键决策、未完成事项及消息引用；
- 附件是否实际携带、工具结果是否仅作历史证据；
- 不能恢复的运行时状态与迁移损失；
- 用户预览后的脱敏结果。

先做确定性的文本选取和分块，不默认向云端发送原件。AI 摘要是可选项：明确模型、费用与外发范围，摘要保留原文定位。提示注入警告只是辅助，真正的安全边界是隔离历史与执行入口。

## 4. 适配器架构

建议拆成三个独立职责，而不是一个万能 `migrate()`：

- `SourceAdapter`：识别用户选定输入、报告版本、预览、流式读取、输出规范化事件。
- `ArchiveCodec`：读取/写入 Staithe 包及外部导出格式；只处理数据，不启动应用。
- `TargetConnector`：生成交接材料、打开应用/来源，或提出经过验证的恢复计划。

每项能力携带：`status`（unknown/documented/fixture-tested/integration-tested/unsupported）、产品版本范围、平台、证据、约束。注意：`documented` 是来源产品有文档，不代表 Staithe 已经实现。

流程建议：用户选择来源 → 只读预览 → 映射与缺失报告 → 用户确认 → 分批事务导入 → 检索/详情 → 交接预览 → 明确确认目标动作。

导入任务运行在独立 worker/utility process，采用背压和分页；主进程只编排授权与 IPC。渲染进程继续使用具名 preload API，不能获得任意路径读写或任意命令执行能力。

## 5. 包格式与存储

建议在真实格式验证后设计 v2 容器，而不是立刻冻结规范：

```text
manifest.json
conversations/<id>/conversation.json
conversations/<id>/messages.jsonl
assets/<sha256>
reports/import.json
```

manifest 应包含格式版本、最低读取版本、生成器、文件大小与散列、来源与完整度。原件可以在本地档案库保留，但对外导出默认不携带全量原始日志、登录数据或未经选择的附件。

不能只依赖文件扩展名：检查 magic、版本、条目数、单文件大小、解压后总大小和压缩比；拒绝路径穿越、绝对路径、符号链接与超预算内容。加密包还需限制 KDF 参数和内存消耗；密码仅在主进程短时使用，不写日志，不尝试破解未知加密格式。

索引建议 SQLite + FTS5；中文检索效果必须用真实语言的合成夹具验证，不能把默认 tokenizer 当作已解决中文全文搜索。大附件使用内容寻址文件存储，不把二进制全塞进数据库。

现有 `library.json` 迁移必须：先备份 → 写入新库 → 数量/散列核验 → 成功后切换 → 保留回退。旧 Ember 包与本地链接兼容仍保留。

## 6. 优先级与验证门槛

### 阶段 A：三类输入的小规模验证

建议先用不同性质的输入验证架构，而不是同时实现十几个客户端：

1. **Cindy `.cshare`**：官方源码已有 manifest、消息、媒体及 harness 转录层，可先做只读解析。[C1–C3]
2. **一个云端聊天导出包**：优先 DeepSeek；也可用 ChatGPT/Claude 官方导出建立夹具。没有真实脱敏样本前，不预设最终字段和文件布局。
3. **一个本地 harness 日志**：Claude Code 或 Codex，固定版本与来源权限；只读归档与原生 resume 分开验收。

每个验证必须交付：格式/版本说明、合成或用户提供的脱敏夹具、字段映射、缺失矩阵、重复导入策略与失败路径测试。无法确认格式时保持“待验证”，不猜测路径扫描。

### 阶段 B：可用的本地档案产品

实现 v2、SQLite、批量导入/取消、来源筛选、分页搜索、附件缺失提示、导入报告和删除。新增数据源与读取范围始终由用户选择。

### 阶段 C：跨客户端交接

先做复制/文件交接和打开目标应用。默认不自动发送、不执行历史命令；目标不支持预填时明确提示用户粘贴。交接记录保存来源和目标关联，以便之后重新导入新会话并显示“从这里继续”的谱系。

### 阶段 D：有证据的原生迁移

优先复用供应商正式导入向导或公开恢复入口，不伪造其内部数据库。只有具备版本探测、备份、预演、冲突处理、回读与回滚，才让 Staithe 执行目标写入。恢复按钮不能仅凭命令存在就启用：还要校验会话 ID、工作区和运行时兼容性。

以上为依赖顺序，不是工期承诺。精确排期应在阶段 A 获得样本之后再做。

## 7. 安全与测试验收

- 仅读取用户明确授权文件/目录；排除凭据、Cookie、登录态和无关记录。
- 分享 URL 不作为批量爬取入口。后续支持时需域名白名单、跳转重新验证、SSRF 防护，拒绝本地/内网地址；绝不复用用户隐藏登录态采集。
- 日志、Markdown 和 HTML 都是非可信数据。HTML 只提取内容，不渲染脚本；图片/附件不自动联网加载。
- 边界测试覆盖截断 JSONL、未知版本、超大/压缩炸弹、坏编码、分支/工具块、重复导入、取消重试、缺失附件和权限不足。
- 性能验收使用合成大库，记录机器、数据量、内存与延迟；不凭小演示库保证万条会话体验。
- 原生恢复的真实验证必须另获授权；先在临时用户目录或隔离测试账号中验证，不使用真实会话。
- 遵循仓库 TDD：先写相关测试；最小测试后 typecheck；核心/UI 改动跑覆盖率；IPC/桌面改动构建并跑隔离 E2E。
