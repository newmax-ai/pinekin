# 来源直读改造与验证

日期：2026-10-18。代码基线：`1b8d2d9` 之后的未提交改动。

## 完成范围与未完成范围

本批将默认入口从“本地档案 → 导出”改为“连接来源 → 浏览／查找目录 → 按需读取 → 检查目标能力”。来源服务完全不依赖档案库，旧档案保留在独立兼容入口。

**目标自动创建、打开与继续仍未启用。** Cindy 普通桌面会话已增加受限正文直读；分叉、协作、远程及未知结构仍拒绝。macOS 已增加禁止写入的 WAL 只读路径，但不把来源读取称为“一键跨 App 同步”。下方历次验收记录保留当时结果；当前能力以“多来源详情修复”及契约、安全章节为准。

自动验证只使用本仓库构造的合成日志、合成数据库和隔离 userData。后续详情修复经用户问询卡片单独授权，对已连接 Cindy 做版本、表结构和内容类型的只读诊断；不输出正文、不读取凭据、不修改数据库、不重新导入真实会话。其余来源仅检查代码与合成夹具。

## IPC 契约

具名桥：`window.staithe.sources`。每个通道同时检查发送窗口和顶层 frame。

| 方法 | 通道 | 校验与行为 |
| --- | --- | --- |
| `connections()` | `pinekin:sources-connections` | 仅读连接配置和内存状态，不触发来源扫描 |
| `autoConnect(source)` | `pinekin:sources-auto-connect` | 默认入口；来源枚举，主进程定位固定位置、复用连接并等待首次扫描；返回最新 `{ connections, warnings }`，扫描失败不冒充成功；不打开文件选择器，不接受 renderer 路径 |
| `connect(source)` | `pinekin:sources-connect` | 显式备用入口；系统对话框选择根，不接受 renderer 路径；确认后保存授权、刷新并等待扫描，返回真实连接状态；取消返回 null |
| `refresh(id)` | `pinekin:sources-refresh` | UUID；启动后台目录检查，同连接在途任务合并；已有目录保留，完成后原子替换；不等待扫描结束 |
| `check(query)` | `pinekin:sources-check` | strictObject；可选 ≤100 个连接 UUID、64 位十六进制 selectedId、automatic/manual 模式；只检查已授权连接并等待完成，返回目录 version、连接状态及选中条目的最新元数据／null；不读取正文，不接受路径 |
| `cancel(id)` | `pinekin:sources-cancel` | UUID；扫描失效，保留已发现目录，`total=null` |
| `disconnect(id)` | `pinekin:sources-disconnect` | UUID；串行移除持久化授权，撤销读取并清空索引，不删除来源 |
| `page(query)` | `pinekin:sources-page` | strictObject；可选来源／连接 ID，查询 ≤200 字，offset ≥0，limit 1–100；返回可见元数据、目录 version 及完整筛选结果 snapshot |
| `read(id, cursor?)` | `pinekin:sources-read` | 64 位十六进制 opaque ID；只从当前索引映射路径。数据库来源可传 strictObject 游标（非负安全整数 offset/textOffset、可选 64 位十六进制 snapshot；非零偏移必须带 snapshot），返回有界文本、window、实际读取 revision 和说明，不归档；日志来源暂不接受非初始游标 |

`SourcePage.snapshot` 是按来源、连接、关键词筛选并排除已知不支持条目后的完整有序元数据结果哈希，包含未加载页，分页间一致。它忽略单纯的已读状态变化，但条目被过滤会改变结果。`check` 保留全局 `version`；全局变化后，前端用 `page(limit:1)` 取得当前范围指纹，不变则不提示列表更新、也不阻断后续分页；只散列内存元数据，不额外读取正文。

日志正文暂沿用既有解析器：输入 5 MiB，压缩展开与窗口另有预算；日志流式分页尚未实现，旧整文件大小过滤仍是待改边界。数据库来源从 2026-10-19 起改为下述按次窗口预算，不再以总字节数／总条数判断不支持。普通读取失败保留重试；明确不支持的格式和会话边界仍过滤，不删除来源。

### 大数据库会话的有界阅读（2026-10-19）

- **列表不因大小缩水**：NewMax／Cindy 超过旧 5 MiB 或 10,000 条总预算，仍保留在目录、搜索与计数中。目录不新增正文扫描，也不返回正文；不能把安全读取预算等同于格式不支持。
- **限制每次输出**：固定 SQL 每次最多投影 100 条来源消息，每条至多 16,384 个 Unicode 码点；先提取 NewMax 的用户 displayContent、Cindy 的用户 JSON 文本，再切片，不把截断 JSON 或隐藏附件当正文。遇到长消息先停在当前片段，next 从同一条消息的后续码点继续；尾段读完再进入后续消息。不改动来源，旧档案导入上限与完整快照校验保持不变。
- **明确部分视图**：`SourceContent.window` 返回 offset、textOffset、totalMessages、snapshot、hasMore 和可选 next 游标。来源消息数可能包含内部或空白记录，不冒充当前可见文本数。界面仅挂载当前片段，通过上一段／下一段重新读取；长片段默认仍限量展示，展开按钮标注当前片段。只有末段显示对话结束，不以局部内容冒充完整会话。首段全为内部／空白记录时仍可继续翻段。
- **跨页一致性**：游标绑定来源、会话 ID 与 DB/WAL 文件身份、大小、mtime/ctime；不使用易变的 SHM 锁读标记。读取期间变化或续读时版本改变则报可重试错误，保留当前片段与列表，不混合不同版本；可从头重新读取。保守地将同库其他写入也视为变化。后台目录 revision 机制不变。
- **安全边界**：每次续读仍校验发送者、参数、授权与文件身份，使用禁止写入和网络的独立进程；结构／隐私／分叉／协作等原门禁不放宽。保留子进程超时和输出上限，不是取消全部资源保护。未读取真实客户端数据，未创建 Electron 验收窗口。

### 启动恢复已授权连接

主进程在创建首个窗口前调用内部 `SourceBrowser.restoreConnections()`：只从 `connections.json` 恢复已授权位置，将尚未加载的位置置为 `scanning`，后台扫描不阻塞首屏。界面已有轮询自动更新“加载中”和会话数量，无需手动刷新。该方法不调用自动定位，不增加连接，不完整解析会话正文，不重写授权配置；没有新增 IPC。Claude Code 的标题回退会从限量头部读取首条有效用户输入的短文本，范围见下文。

重复调用启动恢复只处理 `idle`，不重启正在扫描、已完成、失败或用户暂停的位置。各来源独立完成／失败；后续自动检查按下文限频与失败退避执行，手动刷新可立即重试。连接配置损坏时仍创建窗口，由现有 API 将真实错误交给界面，不静默覆盖文件。

启动增量按 TDD 验证：6 项服务测试覆盖保存范围、未授权／断开排除、幂等、暂停、单项失败与损坏配置；组件测试覆盖加载中自动更新为数量。相关最小回归 63 项通过，类型检查通过；本轮全局覆盖率 35 文件、494 项通过，行 98.52%、分支 89.18%。桌面重启自动加载、排除未授权默认目录、失败隔离及手动修复、损坏配置仍可打开窗口均经隔离合成数据验证。

### 不打断阅读的后台检查（2026-10-18）

- **触发与节流**：窗口聚焦／恢复可见后防抖 600 ms 检查，可见时每 60 秒兜底；隐藏时清除定时器，卸载移除监听。自动检查至少间隔 15 秒。主进程对失败／部分失败的连接按 30 秒起指数退避，最高 5 分钟；手动刷新绕过冷却但合并在途扫描，不恢复已断开连接。用户暂停的来源不被自动恢复。
- **稳定快照**：首次扫描仍渐进展示；再次扫描在独立 Map 中建立草稿，保留旧目录、计数及按需读取能力。成功后一次发布增删与元数据变化；失败保留旧目录，部分不可访问时保留相应旧条目并明确统计不完整。`refreshing` 与首次 `scanning` 区分。每次检查串行处理连接，单连接并发请求合并，不以后台刷新禁用阅读与导航。
- **读取成本**：日志遍历仍需文件属性检查（并非 O(1) 文件系统监听），以 dev/ino/size/mtime/ctime 指纹复用未变文件元数据，只对新文件／变化文件重开有限预览。数据库及 WAL/SHM/journal 指纹不变时不启动 SQLite 查询；有变化仅重新查询目录白名单，逐行 revision 保证其他会话变化不提示当前正文更新。缓存仅在进程内，不建立正文副本或写入来源。
- **目录体验**：列表顶部可原位更新；向下翻找、列表内焦点或已有待更新提示时保持原顺序，显示“列表有更新，点击查看”。点击才加载最新顺序并返回列表顶部，保留已加载条目范围及选中正文。多页合并校验 version，变化时不混合新旧页；搜索保留关键词、分页与滚动，同样先提示。无变化不重新分页，来源切换／断开后的迟到结果不覆盖新视图。
- **正文体验**：后台检查只返回选中条目 revision，不自动重读正文。变化提示“此对话有更新”，点击后保留阅读容器与滚动位置，失败保留原文并就地提供“重试读取”。仅当前旧消息完整保持不变且新增消息时提供“跳到新增消息”，编辑／删除不冒充追加。来源删除显示明确旧快照提示，不再重读或提供重试；断开仍撤销阅读入口。日志返回实际读取时的文件 revision，SQLite 返回同一只读事务中的会话 revision，避免目录版本滞后造成重复提示。
- **手动入口**：列表标题栏刷新当前来源（所有会话下刷新全部已连接来源），完成目录检查后重新读取该范围内当前打开的会话，即使目录版本未变化也重读正文。刷新忙碌态覆盖目录检查和正文读取，避免重复请求；保留列表分页、选择和阅读位置，失败保留原文。连接卡片仅管理授权，不再提供逐位置刷新或暂停；手动更新统一使用主列表刷新入口。来源详情不再显示底部按钮或底栏；后台检查及读取失败后的能力核对不会触发重读循环。切换会话／来源、断开或卸载后的旧请求不得覆盖当前内容。
- **边界**：SQLite 正文变更提示依赖受支持来源维护会话更新时间／消息计数等目录元数据；绕过客户端、只改消息而不更新会话元数据不保证自动识别，可通过列表标题栏手动刷新重读当前正文。此机制不是逐字推送、目录事件监听、全文索引、原生恢复或双向同步。

本次刷新机制验收：新增服务／组件 **16 项**及隐藏窗口桌面 **2 项**通过，覆盖增删、文件缓存、WAL、检查合并、失败退避、正文版本、搜索／列表分页稳定、真实滚动、删除快照、可见性与卸载清理。共同工作区的完整单元／集成／组件 **46 文件、636 项通过**，行 **98.27%**、分支 **88.07%**；类型检查与构建通过。完整桌面首次 **69 / 71**，另两项是并行界面／来源展示改动后的旧断言（搜索项圆角、标题前缀），仅修断言后定向 **2 / 2** 通过；合并覆盖全部 71 项，不宣称第二次重跑了全套。验证只用合成数据与隔离 home／userData，从创建起隐藏并验证未发生 show/focus。

## 自动定位（2026-10-18）

`src/main/source-discovery.ts` 的默认交互是「连接 App → 打开该 App 开关」。打开弹窗不探测，打开开关才查找固定位置并首次读取；操作中禁用冲突开关和关闭动作。连接后保留弹窗，点击「完成」才进入本次成功连接的来源；多个 App 则进入所有会话，未新增连接时仅关闭并保留当前筛选。未找到时开关仍关闭，可再次打开重试；已保存但读取失败仍保持授权开启，并明确显示失败原因，卡片信息区直接提供自定义位置。只读发现不递归搜索主目录，不读取认证／配置文件，不启动客户端。主进程通过 Electron 提供 home / appData；环境覆盖只使用 Pinekin 进程实际继承的变量，不读取 shell 配置、不猜测另一个进程的启动环境。

### NewMax 共享数据库链接

NewMax 的 `electron/libs/devInstanceRole.ts:5–10、63–70` 明确支持开发副本通过软链接共享数据库。本轮仅用 `lstat/realpath` 核对了用户报错入口：配置目录 `.newmax-clean/newmax.db` 是指向默认 `.newmax/newmax.db` 的链接；没有读取真实数据库内容或凭据，也没有修改链接。

- 仅针对 NewMax 已知入口解析链接；最终目标必须是规范化后的配置数据目录或默认 `.newmax` 目录里的普通 `newmax.db`。支持相对／绝对文件链接和数据目录别名，不扩大到任意其他文件。
- 解析前后复核入口身份与真实路径，再以 `requireCanonicalPath` 交给连接服务；如果父目录在交接时变成链接，则拒绝重新解析到新目标。连接配置只保存真实路径，之后刷新和重启不再跟随副本链接改指向；重复连接按真实路径去重。
- 断链、循环、目录目标、其他文件名及范围外目标明确报错，不自动回退到别的库。用户需要范围外位置时，仍通过系统选择框选择实际数据库文件；其他 App 和 SQLite 副文件的拒绝链接策略不变。
- TDD 先复现 10 项失败，再通过链接／发现／来源／SQLite／启动的 57 项定向回归；共享稳定覆盖率 37 文件、532 项通过，行 98.37%、分支 89.15%。类型检查、构建及完整后台 Electron **61 / 61** 通过。新增桌面用例使用合成活跃 WAL 和开发副本链接，验证零文件选择框、按需正文、真实路径持久化、链接改变后重启仍读原目标，以及 DB/WAL/SHM 与入口链接不被写入。

所有来源都保留已有授权位置（包含自定义位置），启动后自动重新加载这些位置，不要求重复选择文件或手动刷新；未连接和已断开的 App 不参与启动扫描。空列表的「刷新」和主列表顶部刷新入口继续用于手动更新或失败后的重试。底层自动连接 API 仍复用同一规范化路径的连接 ID，不增加条目；已连接 App 的开关保持开启，卡片合并显示数量，并直接呈现位置统计与失败原因，不重复添加。除上述经过校验并固定真实路径的 NewMax 共享数据库入口外，默认候选存在符号链接或经过链接时仍拒绝自动读取；自定义位置只能通过主进程对话框明确选定实际文件。权限失败与未找到区分，单点失败以 warnings 返回，不吞掉已连接位置；异步探测后、每个连接前再次核验发送者。`autoConnect` 等待首次扫描并回传最新状态；位置已保存但数据库读取失败时，界面保留失败原因，不自动关闭或显示成功。后续来源变化由可见窗口低频检查与回到窗口检查发现，手动刷新仍可立即触发。

侧栏来源以已保存的位置授权为准，不以是否有会话或是否 `ready` 为准；待刷新、统计中、部分可读、已暂停和读取失败仍有入口。同一 App 多位置只显示一项，全部断开后才移除；当前筛选和浏览历史中的失效来源同步回到「所有会话」。连接来源弹窗在同一网格展示所有已适配 App，不再使用国内／国际筛选；标题描述紧跟标题。每个 App 一张卡片，所有行按最大内容所需高度统一等高，不设固定像素高度，不分已连接和添加来源两组。同 App 的多个位置统一通过一个 small 开关连接／断开，开关本身即表示授权状态，不再附加连接状态标签；卡片直接整合合并会话数和简洁的位置统计；只要任一位置统计未完成，就显示已发现数量与未完成提示，不冒充完整总数。Codex 默认目录以「普通会话／归档会话」呈现，悬停保留原位置名；不再使用 details／summary 或逐位置操作。信息区随长错误、异常目录／链接计数与更多位置自然撑高，并同步整个网格的卡片高度；无内容时隐藏，不保留空白信息区。超出可用高度时由弹窗内容区整体滚动，卡片内部不再嵌套滚动。关闭时在同一个 busy 操作内串行撤销所有位置，每项成功后同步真实状态；中途失败保留剩余授权，开关不假装关闭，重试仅处理剩余位置。全部撤销后清理失效来源筛选和历史，不删除源文件。

## 总数的含义

- 不连接时显示“未连接”，不是 `0`。
- 启动时自动加载已授权来源，侧栏显示“加载中”；不自动发现未连接 App。底层仅查询配置不隐式触发扫描，“待刷新”仍是兼容状态，但不再是正常桌面启动默认。
- 加载中显示已发现数量；只有 `ready` 才给出完整 `total`。
- 无权限子目录、取消和首次失败保持 `total=null`；后台刷新整体失败保留上次成功计数，但状态明确显示读取失败，不能冒充最新统计。管理连接显示原因与未访问／链接计数。
- 扫描覆盖授权范围内的匹配文件／会话行；列表、搜索和连接数量统一排除已知不支持的条目。无 10／50 条发现上限，每页默认 50 条只是显示分页。
- 同一来源根重复连接复用连接；多个位置的条目不做语义合并。此数量不是账户云端总量，也不是独立逻辑线程的跨文件去重总量。
- 搜索覆盖全部已发现标题、相对项目目录、来源 ID 和日志文件名；提取出标题后仍能按原 UUID 文件名查找。未实现全文搜索或持久化正文索引。
- `SourceSearchDialog` 独立维护查询结果、分页、加载与错误状态；输入、清空、无结果、重试和关闭只影响弹层。主列表保留原有来源、已加载页、计数、滚动和当前正文，点击结果才切换会话。返回／前进不记录搜索词，只记录来源与实际打开的会话；过期或关闭后的搜索响应不会回写主列表。
- 搜索弹窗宽 660px、高 500px，分别受视口宽减 48px、高减 64px 限制，不按结果数量或加载／空／错误状态伸缩。搜索框固定在滚动区外，结果使用剩余高度内部滚动，空结果不占用结果列表高度；分页及清空关键词保持相同外框尺寸。

### Claude Code 标题提取（2026-10-18）

旧列表只识别日志开头 64 KiB 的 `custom-title`，且正文超过 5 MiB 或位于子会话目录时完全跳过元数据，导致普通日志普遍退回 UUID 文件名。现在：

- 对未压缩 Claude 日志先分别读取头部和尾部至多 64 KiB；小文件只读一次。标题仍缺失且日志大于 64 KiB 时，额外读取连续头部至多 1 MiB，以覆盖跨越初始窗口的页面快照／前置上下文；单文件最多读取 1 MiB + 128 KiB。窗口边界的残缺 JSON 行丢弃，按完整记录解析，不用正则从正文中抓取伪标题。
- 按 `custom-title.customTitle` → `ai-title.aiTitle` → `summary.summary` → 首条有效用户输入 → 文件名选取；同类使用窗口中最后一条有效值，较晚的自动标题不能覆盖自定义标题。没有读取整份日志，因此窗口之外的重命名不能保证发现。
- 首问回退仅来自连续头部 `user.message.content` 的字符串或 text 块，不从不连续尾部续问推断首问。跳过 `isMeta`、压缩摘要、仅转录可见记录、工具结果、本地命令／输出及纯 IDE 包装；去除开头系统／IDE 提示，只取有效首行、限制 80 个 Unicode 字符加省略号；浏览器任务先去除完整的页面包装。显式标题仍限制 200 个 Unicode 字符。
- 大日志、子会话仍可提取标题和来源 ID，但 5 MiB 正文上限、子会话与父链限制不变；损坏或无标题的文件仍列出。Codex 增量策略见下文；其他来源策略不变。

## 文件与 SQLite 安全补强

1. 数据读取层不跟随符号链接；NewMax 自动定位层可按上文规则解析已知共享入口，并只将校验后的真实路径交给读取层。授权根规范化后固定保存，访问前再次核验范围。
2. 普通日志打开前后对照 dev/ino，交付前再验证路径身份；正文中途变化则拒绝。合成竞态测试确认打开到外部不同 inode 时，在 `read` 前即拒绝。
3. 不能仅依赖 SQLite `readOnly` 来宣称无写入：WAL/SHM 仍存在副文件维护风险。
4. `source-sqlite.ts` 目前仅在 macOS 验证：通过 `/usr/bin/sandbox-exec` 强制禁止全部文件写入与网络，调用固定 `/usr/bin/sqlite3`，使用 `mode=ro`、`query_only=ON`、`trusted_schema=OFF` 和单一事务取得一致投影。用户目录、挂载卷及来源同目录默认禁止读数据，只给授权 DB/WAL/SHM 开例外。CLI 的初始化文件固定 `/dev/null`，不继承宿主凭据环境，不执行来源 SQL／工具指令。
5. 活跃 WAL 由 SQLite 读取已提交内容；未提交事务不进入结果。仅当 WAL/SHM 均不存在时使用 `immutable=1`，结束后再次确认无副文件、主文件未改变；活跃模式核验主文件与副文件身份。回滚事务日志、符号链接、不可用的安全读取组件及其他平台均 fail closed。不复制整库，不 checkpoint 或删除副文件；**不要要求用户手动删除 WAL/SHM**。
6. SQL 只投影白名单表列；正文查询前在同一事务内限制普通非隐私、非分叉 App 会话。2026-10-19 起将旧 5 MiB／10,000 条总预算替换为每次 100 条、每条 16,384 个码点的阅读窗口，并明确续读游标。会话 ID 采用 UTF-8 十六进制值，不拼入 SQL 语法；窗口偏移必须通过安全整数校验。独立进程 30 秒超时、64 MiB 输出预算仍保留。正文含 NUL 时明确报当前分段方式未支持并保留条目，不利用 SQLite 在空字符处截断的行为伪装读取成功。
7. 数据库 ID 必须是非空、有限长度字符串且唯一；重复 ID 停止扫描，不能静默 Map 覆盖后报完整总数。没有放宽 NewMax 列／JSON 一致性、Cindy 正文或目标接续门禁。
