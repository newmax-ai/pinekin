# 来源直读改造与验证

日期：2026-10-18。代码基线：`1b8d2d9` 之后的未提交改动。

## 完成范围与未完成范围

本批将默认入口从“本地档案 → 导出”改为“连接来源 → 浏览／查找目录 → 按需读取 → 检查目标能力”。来源服务完全不依赖档案库，旧档案保留在独立兼容入口。

**目标能力更新（2026-10-19）：已接入 macOS Codex 的完整文本读取、目标程序隔离预演、新会话日志创建、备份、散列回读、幂等重试、撤销与深链打开请求；真实目标桌面展示和下一轮对话尚未实机验收。** 详情见 [目标能力](target-capabilities.md)。 Cindy 普通桌面会话已增加受限正文直读；分叉、协作、远程及未知结构仍拒绝。macOS 已增加禁止写入的 WAL 只读路径，但不把来源读取称为“一键跨 App 同步”。下方历次验收记录保留当时结果；当前能力以“多来源详情修复”及契约、安全章节为准。

自动验证只使用本仓库构造的合成日志、合成数据库和隔离 userData。后续详情修复经用户问询卡片单独授权，对已连接 Cindy 做版本、表结构和内容类型的只读诊断；不输出正文、不读取凭据、不修改数据库、不重新导入真实会话。其余来源仅检查代码与合成夹具。

## 国内 Harness 来源扩展（2026-10-19）

新增 **WorkBuddy 与 Qwen Code** 独立适配，不共享 Claude 的格式／归属推断，不顺带宣称 CodeBuddy、Gemini CLI 或网页聊天已支持。WorkBuddy 只浅层发现 `.workbuddy/projects/<project>/*.jsonl`，排除 cloud 与 subagents，并有界读取同名 `.meta.json`；Qwen 只发现 `.qwen/projects/<project>/chats/*.jsonl`，不进入工具输出和工作流目录。点击开关才授权；手动位置仍只经系统选择框，IPC 不增加任意路径能力。

两者在目录阶段完整检查父链和已知不支持边界，只保留元数据／轻量结构，不返回或落盘正文；正文沿用两遍流式扫描和 Unicode 分段游标。WorkBuddy 的目录 revision／正文 snapshot 同时绑定 JSONL 与 sidecar，侧车变化不得继续旧片段；侧车预算 64 KiB，符号链接、身份变化及损坏均明确报错。WorkBuddy 的旧式重复 ID、分叉、压缩、重发回退与子会话，Qwen 的分叉、回退、压缩及托管边界均保留明确限制，不猜测有效分支。原 App 打开和目标恢复能力没有因来源增加而放宽。

官方版本／提交证据、完整路径、兼容范围及测试约束见 [国内来源契约](domestic-sources.md)。新增合成服务／组件测试和隔离桌面用例；遵守主 dev 限制，不启动 Electron E2E 副本或重启主 dev，不用真实会话代替测试。

## 原会话打开与辅助文本操作（2026-10-19）

本节取代此前的来源交接表单。原会话定位与跨 App 创建分别受能力门禁控制；复制和导出属于「更多」中的辅助操作，不能作为跨 App 接续成功的证明。

- 标题不附加「来源直读」标签。主操作使用 small 按钮，标题优先占宽，窄窗口下操作自然换行并靠右；样式限定在来源详情，不影响历史档案页头。
- `SourceActions` 组件不再展示目标下拉、任务输入、默认末尾 10 条或敏感内容确认。原会话打开只在来源元数据与系统协议关联检查通过后显示；缺少原 ID、辅助记录、未支持来源或无匹配协议时不留禁用占位，具体原因以「更多」菜单说明展示，不猜链接或绕过门禁。检查失败可重试。
- NewMax 与 Codex 使用白名单协议发送原会话定位请求；仅报告操作系统已受理请求，不宣称目标端已显示或恢复成功。原客户端可能使用不同数据目录或拒绝定位，真实结果由原客户端展示。
- 复制／导出直接使用 `source-transcript.ts` 生成的通用文本，不指定目标。当前已读片段的全部文字均包含，不再默认只保留末尾 10 条；分段时菜单明确标「复制当前片段／导出当前片段」，位置、读取说明与已知旧快照状态随文本保留，不自动补读其他片段。
- 文本按实际 UTF-8 字节数限制为 5 MiB，包含 JSON 转义开销，超限明确拒绝，不悄悄截断。空文本不可操作。没有自动摘要、模型调用、脱敏或目标发送；不执行正文内的链接、HTML、工具或命令。
- 原会话动作与复制／导出操作中禁用重复触发；失败可重试，关闭菜单恢复触发焦点，异步结果不能覆盖新选会话。导出取消不报成功，不保存正文到 Pinekin 档案库。
- 主入口改为「在其他 App 继续」，先选目标，不替用户默认选择 Codex。点击 Codex 目标卡片后读取其已保存的本地项目元数据，列出项目名称和路径，支持搜索、刷新与直接点选；只打开列表不创建。另保留「独立会话继续」及「选择其他文件夹」，后者才使用系统目录选择器，取消不配置、不创建。后续后台完成自动识别和必要配置，首次也不要求确认安装／数据位置。多根和共享目录等无法准确按 cwd 归属的项目显示限制；不将原生项目成员关系写入冒充已支持。字段证据与边界见 [已有项目列表](codex-project-catalog.md)。所选项目路径可以显示；安装与数据目录仍只放在目标设置，不恢复「连接并继续」步骤。随后从来源第 0 条补读完整一致快照，以目标程序隔离验证 UI 历史，再创建全新日志、回读和请求打开。复制仍只处理当前片段；两者不混用。首次配置可取消，创建／打开失败可重试，未变化的目标可撤销。用户已确认原有独立会话接续接通；新增项目归属的 GUI 与下一轮对话仍待验收，协议与证据见 [目标能力](target-capabilities.md)。

新增具名桥为 `window.staithe.sourceActions`，所有通道均复用主窗口与顶层 frame 校验；Codex 新建通道在独立模块中注册：

## IPC 契约

具名桥：`window.staithe.sources`。每个通道同时检查发送窗口和顶层 frame。

| 方法 | 通道 | 校验与行为 |
| --- | --- | --- |
| `connections()` | `pinekin:sources-connections` | 仅读连接配置和内存状态，不触发来源扫描 |
| `autoConnect(source)` | `pinekin:sources-auto-connect` | 默认入口；来源枚举，主进程定位固定位置、复用连接并等待首次扫描；返回最新 `{ connections, warnings, notices? }`；`notices` 表示未找到本机会话等正常中性提示，不作为错误警报或混入完成后的失败汇总，`warnings` 仍保留权限／读取等异常；扫描失败不冒充成功；不打开文件选择器，不接受 renderer 路径 |
| `connect(source)` | `pinekin:sources-connect` | 显式备用入口；系统对话框选择根，不接受 renderer 路径；确认后保存授权、刷新并等待扫描，返回真实连接状态；取消返回 null |
| `refresh(id)` | `pinekin:sources-refresh` | UUID；启动后台目录检查，同连接在途任务合并；已有目录保留，完成后原子替换；不等待扫描结束 |
| `check(query)` | `pinekin:sources-check` | strictObject；可选 ≤100 个连接 UUID、64 位十六进制 selectedId、automatic/manual 模式；只检查已授权连接并等待完成，返回目录 version、连接状态及选中条目的最新元数据／null；不读取正文，不接受路径 |
| `cancel(id)` | `pinekin:sources-cancel` | UUID；扫描失效，保留已发现目录，`total=null` |
| `disconnect(id)` | `pinekin:sources-disconnect` | UUID；串行移除持久化授权，撤销读取并清空索引，不删除来源 |
| `page(query)` | `pinekin:sources-page` | strictObject；可选来源／连接 ID，查询 ≤200 字，offset ≥0，limit 1–100；返回可见元数据、目录 version 及完整筛选结果 snapshot |
| `read(id, cursor?)` | `pinekin:sources-read` | 64 位十六进制 opaque ID；只从当前索引映射路径。数据库和三类日志来源均接受 strictObject 游标（非负安全整数 offset/textOffset、可选 64 位十六进制 snapshot；非零偏移必须带 snapshot），返回有界文本、window、实际读取 revision 和说明，不归档；日志游标绑定实际文件指纹，不是任意文件字节偏移 |

`SourcePage.snapshot` 是按来源、连接、关键词筛选并排除已知不支持条目后的完整有序元数据结果哈希，包含未加载页，分页间一致。它忽略单纯的已读状态变化，但条目被过滤会改变结果。`check` 保留全局 `version`；全局变化后，前端用 `page(limit:1)` 取得当前范围指纹，不变则不提示列表更新、也不阻断后续分页；只散列内存元数据，不额外读取正文。

数据库与日志来源均已改为按次窗口预算，不再以旧 5 MiB 总字节数／10,000 条消息限制判断不支持。日志的旧 20,000／50,000 行上限也不再用于来源阅读；完整档案导入仍保留旧预算。普通读取失败及工作预算耗尽保留重试；明确不支持的格式和会话边界仍过滤，不删除来源。下方历史记录中的旧预算以本节和“流式大日志阅读”规则为准。

### Codex 会话 ID 冲突前置过滤（2026-10-19）

- `session_meta.payload.session_id` 明确声明且与 `id` 不一致时，不猜测会话归属，按已知未支持边界过滤，而不是保留一个点击后必然报错的可重试条目。
- 未压缩头部预览、Zstandard 完整元数据扫描与按需正文共用 `codexUnsupportedReason`；目录首次发现便排除已识别冲突，搜索、分页、连接计数遵循同一过滤状态。
- 目录列出后来源才出现 ID 冲突，正文抛出具名 `UnsupportedSourceError`，立即移出可见目录并更新计数／结果快照；不删除原件，来源修复并刷新后重新纳入。已知外部继承与未知历史模式继续拒绝。
- ID 一致、仅声明父会话或子 Agent 的独立文件继续可读，旧格式未声明 `session_id` 也不因此排除。权限、JSON 损坏、暂时读取失败和工作预算限制仍保留重试；不按标题里的任务描述猜测支持性，也不放宽档案导入规则。
- 回归只使用合成普通／压缩日志，覆盖首次过滤、未变化缓存、读取期间变化、修复恢复和损坏保留；桌面夹具隔离 userData，并替换系统剪贴板与文件对话框。

### 流式大日志阅读（2026-10-19）

- **适用范围**：Claude Code 未压缩 JSONL、Codex JSONL／Zstandard、DeepSeek Harness v4 JSONL／Zstandard。Claude 压缩日志、逻辑父链／压缩边界、Codex 外部继承及 DeepSeek 非独立主会话仍未支持；不通过放宽结构门禁伪装兼容。
- **有界流水**：`source-log-file.ts` 每次读取 64 KiB，只累积当前行并执行严格 UTF-8 解码。首遍由 `source-log-index.ts` 校验完整结构，只保留短 ID、位置、长度与标量；第二遍由 `source-log-reader.ts` 仅取当前片段与工具预览，完整扫描结束才返回。正文不落盘，不创建全文缓存；结构索引每次重建，因此续读时间仍与日志大小有关，不宣称随机定位为常数成本。
- **展示预算而非会话大小过滤**：每次最多 100 条文本、每条 16,384 个 Unicode 码点；长单条和合并后的 Claude 助手追加块可在消息内续读，保留换行及 Unicode。offset 对应来源阅读投影中的文本消息，textOffset 为消息内码点位置；窗口总数不是工具数或物理行数。界面沿用上一段／下一段，有限片段不得冒充整段历史。
- **结构语义不变**：Claude 先验证全 UUID 图、缺失父链、循环与单根，再取末条消息父链；消息及工具预览按逻辑链而非物理行顺序整理，不混入旁支。追加块索引校验、旧版无索引片段、可读独立子会话继续保留。Codex 校验 meta、唯一消息 ID、连续 ordinal，不重复投影事件副本、压缩摘要或系统上下文。DeepSeek 校验 v4 独立头、连续 seq、append、角色和唯一 ID，只提取真实问答。
- **压缩严格完成**：使用本地 `createZstdDecompress`，保持最大 8 MiB 解码窗口与严格尾随数据检查，允许合法串联帧；读取总量／展开总量不再限 5 MiB。不能取够一页就提前返回，截断帧可能先吐出合法正文后再报错。没有外部字典或递归解压，不声称所有帧都带 checksum。
- **保留安全工作预算**：单条原始行最多 8 MiB，结构索引记账最多 32 MiB（不是整个进程 heap 的精确上限），每次在块边界检查 30 秒工作时限；超长单行、预算耗尽或超时作为可重试错误保留列表。同一进程最多两个日志读取工作区同时运行，最多八个请求等候，超额请求可重试，避免快速切换会话叠加大量索引内存。工具预览仍最多 100 条、每条 1,024 字符，工具名关联表不再随全部工具历史增长。没有删除所有资源保护，也不声称任意巨大文件都能在时限内读取。
- **一致性与授权**：打开前核验真实路径／普通文件，打开后对照 dev/ino；每遍结束及交付前复核文件身份、大小、mtime/ctime 与授权。续读 snapshot 与实际文件指纹不符时拒绝混合版本；断开会取消结果。不能由 renderer 指定路径或沿日志里的路径读取其他文件。
- **目录前置判定**：移除仅因 stat.size 超过 5 MiB 就设为 unsupported 的分支。大 Claude 文件或头部无法确认归属时使用 `source-log-inspect.ts` 流式完成支持检查，不建立正文索引；BOM 不再让首条 SDK 归属漏检。压缩 Codex／DeepSeek 同样在发布目录前完成解压与已知边界检查。损坏／截断、单行过大和权限错误仍保留，不伪装为零条成功。
- **验证约束**：仅用仓库合成文件；未读取真实会话或凭据。新增压缩探测只使用 Node／Electron 的无 GUI Node 模式；本会话不启动 Electron 桌面 E2E。

本批验收：新增大日志／分段／压缩／父链兼容／取消与并发回归 **25 项通过**。基于 `0a7aaf4` 加本批日志代码与测试的隔离快照：**60 文件、877 项通过**，行覆盖率 **98.30%**、分支 **87.20%**，类型检查与构建通过。快照构建不覆盖主 `out/`；共享工作区同时进行的原 App 打开／目标接续修改不纳入本次隔离结果。桌面断言已同步，本会话未运行 Electron E2E，不以单元测试冒充桌面验收。

### 大数据库会话的有界阅读（2026-10-19）

- **列表不因大小缩水**：NewMax／Cindy 超过旧 5 MiB 或 10,000 条总预算，仍保留在目录、搜索与计数中。目录不新增正文扫描，也不返回正文；不能把安全读取预算等同于格式不支持。
- **限制每次输出**：固定 SQL 每次最多投影 100 条来源消息，每条至多 16,384 个 Unicode 码点；先提取 NewMax 的用户 displayContent、Cindy 的用户 JSON 文本，再切片，不把截断 JSON 或隐藏附件当正文。遇到长消息先停在当前片段，next 从同一条消息的后续码点继续；尾段读完再进入后续消息。不改动来源，旧档案导入上限与完整快照校验保持不变。

## 总数的含义

- 不连接时显示“未连接”，不是 `0`。
- 启动时自动加载已授权来源，侧栏显示“加载中”；不自动发现未连接 App。底层仅查询配置不隐式触发扫描，“待刷新”仍是兼容状态，但不再是正常桌面启动默认。
- 加载中显示已发现数量；只有 `ready` 才给出完整 `total`。
- 无权限子目录、取消和首次失败保持 `total=null`；后台刷新整体失败保留上次成功计数，但状态明确显示读取失败，不能冒充最新统计。管理连接显示原因与未访问／链接计数。
- 扫描覆盖授权范围内的匹配文件／会话行；列表、搜索和连接数量统一排除已知不支持的条目。无 10／50 条发现上限，每页默认 50 条只是显示分页。
- 同一来源根重复连接复用连接；多个位置的条目不做语义合并。此数量不是账户云端总量，也不是独立逻辑线程的跨文件去重总量。
- 搜索覆盖全部已发现标题、相对项目目录、来源 ID 和日志文件名；提取出标题后仍能按原 UUID 文件名查找。未实现全文搜索或持久化正文索引。
- `SourceSearchDialog` 独立维护查询结果、分页、加载与错误状态；输入、清空、无结果、重试和关闭只影响弹层。主列表保留原有来源、已加载页、计数、滚动和当前正文，点击结果才切换会话。返回／前进不记录搜索词，只记录来源与实际打开的会话；过期或关闭后的搜索响应不会回写主列表。
- 搜索弹窗宽 660px、高 500px，分别受视口宽减 48px、高减 64px 限制，不按结果数量或加载／空／错误状态伸缩。搜索框固定在滚动区外，结果使用剩余高度内部滚动，空结果不占用结果列表高度；分页及清空关键词保持相同外框尺寸。

### Claude Code 标题提取（2026-10-18）

旧列表只识别日志开头 64 KiB 的 `custom-title`，且正文超过 5 MiB 或位于子会话目录时完全跳过元数据，导致普通日志普遍退回 UUID 文件名。现在：

- 对未压缩 Claude 日志先分别读取头部和尾部至多 64 KiB；小文件只读一次。标题仍缺失且日志大于 64 KiB 时，额外读取连续头部至多 1 MiB，以覆盖跨越初始窗口的页面快照／前置上下文；单文件最多读取 1 MiB + 128 KiB。窗口边界的残缺 JSON 行丢弃，按完整记录解析，不用正则从正文中抓取伪标题。
- 按 `custom-title.customTitle` → `ai-title.aiTitle` → `summary.summary` → 首条有效用户输入 → 文件名选取；同类使用窗口中最后一条有效值，较晚的自动标题不能覆盖自定义标题。没有读取整份日志，因此窗口之外的重命名不能保证发现。
- 首问回退仅来自连续头部 `user.message.content` 的字符串或 text 块，不从不连续尾部续问推断首问。跳过 `isMeta`、压缩摘要、仅转录可见记录、工具结果、本地命令／输出及纯 IDE 包装；去除开头系统／IDE 提示，只取有效首行、限制 80 个 Unicode 字符加省略号；浏览器任务先去除完整的页面包装。显式标题仍限制 200 个 Unicode 字符。
- 大日志、子会话仍可提取标题和来源 ID，但 5 MiB 正文上限、子会话与父链限制不变；损坏或无标题的文件仍列出。Codex 增量策略见下文；其他来源策略不变。

## 文件与 SQLite 安全补强

1. 数据读取层不跟随符号链接；NewMax 自动定位层可按上文规则解析已知共享入口，并只将校验后的真实路径交给读取层。授权根规范化后固定保存，访问前再次核验范围。
2. 普通日志打开前后对照 dev/ino，交付前再验证路径身份；正文中途变化则拒绝。合成竞态测试确认打开到外部不同 inode 时，在 `read` 前即拒绝。
3. 不能仅依赖 SQLite `readOnly` 来宣称无写入：WAL/SHM 仍存在副文件维护风险。
4. `source-sqlite.ts` 目前仅在 macOS 验证：通过 `/usr/bin/sandbox-exec` 强制禁止全部文件写入与网络，调用固定 `/usr/bin/sqlite3`，使用 `mode=ro`、`query_only=ON`、`trusted_schema=OFF` 和单一事务取得一致投影。用户目录、挂载卷及来源同目录默认禁止读数据，只给授权 DB/WAL/SHM 开例外。CLI 的初始化文件固定 `/dev/null`，不继承宿主凭据环境，不执行来源 SQL／工具指令。
5. 活跃 WAL 由 SQLite 读取已提交内容；未提交事务不进入结果。仅当 WAL/SHM 均不存在时使用 `immutable=1`，结束后再次确认无副文件、主文件未改变；活跃模式核验主文件与副文件身份。回滚事务日志、符号链接、不可用的安全读取组件及其他平台均 fail closed。不复制整库，不 checkpoint 或删除副文件；**不要要求用户手动删除 WAL/SHM**。
6. SQL 只投影白名单表列；正文查询前在同一事务内限制普通非隐私、非分叉 App 会话。2026-10-19 起将旧 5 MiB／10,000 条总预算替换为每次 100 条、每条 16,384 个码点的阅读窗口，并明确续读游标。会话 ID 采用 UTF-8 十六进制值，不拼入 SQL 语法；窗口偏移必须通过安全整数校验。独立进程 30 秒超时、64 MiB 输出预算仍保留。正文含 NUL 时明确报当前分段方式未支持并保留条目，不利用 SQLite 在空字符处截断的行为伪装读取成功。
7. 数据库 ID 必须是非空、有限长度字符串且唯一；重复 ID 停止扫描，不能静默 Map 覆盖后报完整总数。没有放宽 NewMax 列／JSON 一致性、Cindy 正文或目标接续门禁。
