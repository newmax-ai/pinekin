# 接入路线

## 产品原则

Pinekin 是跨 App 会话中转站，不是必须先导入副本的档案库。目标流程：**连接来源 → 浏览和查找全部授权会话 → 选择对话与目标 → 在目标中继续**。这里的接续默认是一次性传递，不是长期双向同步。

## 已落地：来源主数据流（2026-10-18）

- 独立来源服务及主界面，不从 Pinekin 档案数推断外部历史数量。
- 明确授权位置，分批遍历至结束，分页展示与元数据搜索；支持刷新、取消、断开和重启后恢复连接配置。
- 正文按需读取，默认不存正文或原件；不支持、损坏、超限、子会话仍保留目录条目。
- 已有档案入口保留兼容，不自动删除或迁移。
- 目录发现、正文阅读、档案导入、外部打开和原生恢复分别声明，不将一个能力的通过外推到其他能力。

来源覆盖不等于全链路完成。2026-10-19 已补充 macOS Codex 目标日志适配及官方程序回读验证，真实目标桌面展示和下一轮对话仍待验收。来源的 WAL 与 Cindy 正文进展以 [来源直读](source-browser.md) 为准；下方旧阶段优先级不应覆盖其较新能力记录。

## 优先级 1：真实来源覆盖缺口

1. 解决 SQLite 活跃 WAL 的无副作用读取或获得来源官方只读接口。不能通过忽略 WAL、复制整个敏感数据库或让 SQLite 隐式写副文件绕过；不要让用户删除 WAL/SHM。
2. 核实 Cindy 版本、协同/分叉/远程边界，补正文直读；确认会话表兼容性不等于恢复能力成立。
3. 更可靠的来源标题索引、大日志流式投影、Claude Code 压缩和逻辑父链、Codex/Harness 的继承与跨文件历史；每类不支持内容仍保留条目与原因。
4. 按需、可取消全文搜索；不得为了搜索而偷偷将全部正文永久归档。
5. 独立后台 worker、目录变更监听、可重建元数据索引与大型来源的内存预算。预算必须显示状态和续扫入口，不得静默当作完整总数。

## 优先级 2：完成一个真正的目标接续闭环

最小成功标准：**即使 Pinekin 档案库为空，选中来源对话后，也能在明确支持的目标中创建可识别的会话，回读确认，并打开等待用户继续。**

- 已实现 Codex 日志适配：同时创建模型 ResponseItem 与界面 EventMsg，替代不产生 UI 问答的 `thread/inject_items` 方案。官方 0.163.0 二进制已在断网沙箱中逐字回读合成历史，并验证重启回读、生产事务、去重及撤销；主按钮实际创建新目标，不退回复制。每次使用所选且与系统关联一致的程序探测版本、隔离预演，再写入用户授权位置。剩余门槛是目标 GUI 展示和用户下一轮接续的实机验收；详见 [目标能力与证据](target-capabilities.md)。
- 使用合成历史、隔离目标目录和 mock 模型端点验证：创建／注入／重启／打开阶段不产生模型请求，用户主动发送后才开始新轮次。
- 固定客户端版本和协议；只注入明确映射的历史文本，拒绝从来源内容继承系统指令、工具权限、工作区或模型配置。
- 产品写入前必须有版本检测、预演与损失告知、备份、幂等／冲突检测、回读、失败回滚。超时后先查真实状态，不盲目重试追加。
- 只能在验证完整创建／打开／等待输入链路后启用目标按钮；部分成功要明确区分“已创建”“已打开”“可继续”。
- 其余目标分别研究公开历史创建入口；已有原生会话的 resume/fork 或应用内部复制不等于跨 App 任意历史接续。

## 后续迁移完整度

附件、结构化工具、运行态、分支树、模型设置、工作区和权限分别设计与验收。不静默截断、摘要或丢弃后称为原生恢复。可选摘要保留原文引用，明确模型推断与历史事实。

## 发布前

- 已采用 [MIT 许可证](../LICENSE)；发布前核查第三方依赖和素材许可，完成品牌、协议和域名检查。
- 安装包签名、公证、更新以及 macOS / Windows / Linux 独立实机验收。
- 连接配置和旧档案的备份、恢复、删除与容量控制；默认明文不能伪装成加密。
- 明确依赖审计与版本锁定，所有真实客户端数据测试均需单独授权；真实正文与凭据不进入仓库或自动测试。
