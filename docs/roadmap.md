# 接入路线

## 产品原则

名字是 Staithe，意象是让对话停靠、汇聚与再次出发的码头。核心不是“导出聊天记录”，而是让用户拥有自己的对话历史，并能带着上下文继续。工具可以换，思考不必重来。

## 当前阶段 A：小规模只读格式验证

已完成第一批基础闭环：文件选择、来源与损失预览、确认后原件保存、精确文件去重，以及 Cindy 未加密普通 v1 分享包的文本投影。当前为固定源码格式的**合成夹具验证**，不是第三方客户端实机兼容验收。旧 Staithe / Ember 包继续兼容；详见 [格式与支持矩阵](import-formats.md)。

第二类输入已增加 **Codex 独立主会话 JSONL / JSONL.ZST**：固定源码布局、合成回归，并经用户授权做过少量本机日志只读抽样。已增加受限 Zstandard 解压及从 0 连续编号、无外部引用的分页主会话；继承、子会话、缺序号与超限日志仍拒绝，不提供原生恢复。详见 [适配边界](codex-import.md) 和 [本机核验](local-validation-2026-10-17.md)。

已增加 **NewMax 1.1.22 字段白名单快照**与 **Claude Code 完整单根 JSONL 的末条消息父链文本投影**；显式开发批次默认只预演，确认才保存。首批已归档 NewMax 10、Claude Code 10、Codex 3 段；不是全量、持续同步或原生恢复。详见 [格式、使用入口与本机核验](newmax-claude-local-validation-2026-10-17.md)。

下一步按真实缺口排序：Claude Code 压缩与逻辑父链、子会话与跨文件历史的只读模型、大文件的流式解析和预算设计；之后是 Cindy 实际分享包与 DeepSeek 网页聊天导出验证。只有明确授权的目录用于核验，产品不会自动扫描；真实内容不进入测试或仓库。每个适配器都需独立完成：

1. 查验官方格式、实现、授权方式与真实版本，不根据目录名猜测。
2. 用户选择数据位置，只读扫描；不采集密钥、登录态或无关文件。
3. 建立版本化、脱敏测试夹具；覆盖截断、损坏、长记录、工具消息和重复导入。
4. 标记来源、原始 ID、工作区与时间；不能映射的字段明确报告，不静默丢弃。
5. 做增量索引、导入进度、取消与容量控制，避免全库扫描阻塞桌面。

## 之后：可控迁移

- 按目标客户端版本验证官方导入 / 恢复接口。
- 建立能力矩阵：文本档案、附件、工具消息、分支、模型设置、工作区绑定分别标记。
- 目标写入必须先预演，列出损失项和冲突；明确确认后再备份、导入、回读验收。
- 能备份、能回滚、能解释结果后才启用原生迁移入口。

## 跨 harness 接续

优先级顺序：

1. 明文可预览的上下文交接包（已提供基础版）。
2. 支持的目标工具启动入口：明确命令、位置和用户确认，不静默执行。
3. 已验证的目标深链或官方恢复入口。
4. 可选摘要：保留原文引用，区分模型推断与历史事实。

任何分享都先解决敏感信息预览与脱敏，再考虑外部分享页面。不能把带完整上下文的 URL 当作安全分享方式。
