# 已连接来源的统一上下文投影

日期：2026-10-19。适用于 NewMax、Cindy、Claude Code、Codex、DeepSeek Harness、WorkBuddy、Qwen Code 的**来源阅读与文本接续**。不修改来源数据，也不改变旧档案导入的原始保留规则。

## 为什么要统一

日志里的 `role:user` 不一定只包含用户输入，客户端可能在其中加入运行环境、身份、IDE 或项目指令。原先部分来源依靠结构化标记过滤、部分只在界面折叠；复制或接续重新取正文时，仍可能把这些内容作为用户消息带到目标。

现在由 `src/core/source-user-content.ts` 提供共用规则，正文、首问标题、复制／Markdown 和完整接续使用同一政策。目标载荷仍只是用户／助手历史文本，不迁移来源客户端的系统角色、工具权限或运行状态。这里只识别已确认的包装，不是任意提示注入检测器；自然语言指令不能仅因措辞“像提示词”就删除。

## 规则与保留边界

- 只处理**用户消息开头、完整、已知**的包装：`system-reminder`、`environment_context`、`user_instructions`、已知 Codex App 上下文、`recommended_plugins`、IDE 文件／选区通知及 `AGENTS.md / INSTRUCTIONS`；`system-reminder` 的属性只接受已确认的 `data-role="user-context"`。
- 连续或嵌套包装按完整边界处理，不将内部闭合标签误作外层结束；只是文本扫描，不解析／执行不可信 HTML/XML。
- Codex 的已知 IDE 请求前缀继续支持；文件列表与附件占位仍遵守原有单独展示规则，不沿路径加载文件。
- WorkBuddy 只有在已确认前置运行时包装被移除后，才解包整段 `user_query`，保留其中原始用户空白。独立 `user_query` 字面标签不猜测删除。
- 正文中间的引用、代码围栏、引用块、未知属性／标签、完整消息内未闭合的示例、普通自然语言提问及助手文字保持原样。单独的 `local-command-caveat` 不足以证明它是注入，必须保留；已验证的 Claude 本地命令仍由原结构规则排除。
- 不按文本内容猜测角色，不删掉父链节点，不放宽会话归属、分叉／压缩、结构、授权与文件身份校验。

各适配器的结构过滤继续有效：

| 来源 | 原有结构边界 | 统一后的文本路径 |
| --- | --- | --- |
| NewMax | 优先用户 `displayContent`，排除任务／Goal 内部续轮 | 同一只读事务取得有界前缀，按原始码点位置净化片段 |
| Cindy | 先提取用户 JSON 的 `text`，排除非当前问答、工具／推理 | 不二次解析 JSON；复用同一有界前缀与窗口规则 |
| Claude Code | 保留并校验完整父链，排除 `isMeta` 与已知本地命令 | 先拼接整条消息文本块再净化；目录首问和正文同规则 |
| Codex | 排除 system/developer 与已知事件副本 | `codexUserText` 委托共用规则；工具不成为问答 |
| DeepSeek Harness | 只保留 `source.kind:user` 的真实输入 | 文本块提取后、正文长度索引前净化 |
| WorkBuddy | 排除已标记注入；同 ID 助手块语义不变 | 输入文本在长度索引前净化并提取已确认真实请求 |
| Qwen Code | subtype/provenance/thought 门禁不变 | 有效文本在长度索引前净化 |

## 分页与输出

### 日志

两遍流式扫描继续保留：结构校验后，第一遍对净化文本计长、建行号索引；第二遍用同一规则取片段。因此提示包装即使长于 16,384 码点，也不会泄漏为第二页的普通文本。纯注入记录不进入问答计数，但父链节点仍保留。

日志窗口 snapshot 额外绑定 `SOURCE_TEXT_POLICY_VERSION`，与原始文件 revision 分开；旧投影游标不能用于新规则。后台来源 revision 机制不变。

### 数据库

保留原始消息位置、总数、长消息游标和会话级快照语义，不能把内部／空白记录数改成当前可见数组长度。固定 SQL 对当前页用户消息额外投影最多 **65,536 个 Unicode 码点**的前缀，仍在同一只读事务、沙箱和输出预算内；不会返回整份会话或把前缀传给 renderer。

当前片段先按原始长度决定下一游标，再移除落在已确认前缀内的内容；首段只有上下文时可继续翻页。前缀预算内不能确认完整边界时明确报错，包括预算恰好截在下一个起始标签内部的情况（例如 `<syste`），不能把后半标签及内部指令显示或导出。未知标签仍不猜测删除。

数据库正文快照同时绑定文本政策版本；同库其他会话写入或 WAL checkpoint 仍不使所选未变会话失效。

### 复制、导出与接续

- `buildSourceTranscript` 对完整用户消息再次净化并移除纯上下文消息，防止完整旧缓存绕过出口。消息中段保留片段边界，不把中段开头的字面标签当整条消息的新前缀。
- `collectSourceTransfer` 从来源重读，先按原始位置拼回长消息（包括全空白片段），再统一净化完整消息；不使用当前界面片段冒充整条历史。
- `SourceMessage` 不在中间片段上重复识别上下文包装，避免把正文中跨页的代码／标签引用折叠或误删。
- 旧档案解析器的原件、原系统记录保留与来源浏览投影严格区分；不是给历史指令执行授权，也不能保证目标模型不会受到所有未识别文字的影响。
