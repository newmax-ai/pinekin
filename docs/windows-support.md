# Windows 适配与验收

更新：2026-10-25。

## 首版范围

Windows 首版以 **连接日志来源 → 浏览／搜索 → 阅读 → 保存完整接续文件** 为目标。目前 Windows 原生 CI 的依赖安装、单测／覆盖率、生产构建与 Engine 构建已通过；桌面 E2E 尚未完整通过，NSIS 安装包与交互验收未完成，不能标为正式可发布。

- 日志来源：Claude Code、Codex、DeepSeek Harness、WorkBuddy、Qwen Code，继续遵守各自版本与内容边界。
- 主按钮「保存接续文件」：通过现有令牌接口重新读取完整可读历史，以系统保存框选择 `.md` 文件；取消不显示成功，不静默复制正文或路径。
- NewMax／Cindy：非 macOS 暂不支持安全数据库直读，卡片提前解释平台限制，禁用新连接及自定义位置入口。已有连接仍能断开，避免留下无法撤销的授权。
- 原生历史迁移：Windows 没有注册目标；能力检查确认没有已接入目标后隐藏高级迁移和目标设置入口。日志格式可读不代表客户端可恢复或可写入。
- 文件剪贴板：仍未实现 Windows 原生格式；不移除主进程平台拒绝逻辑，不把路径文本当作附件。

## 保存安全修复

「保存接续文件」与「导出聊天记录」已统一使用临时文件完整写入后发布，移除 Windows 分支直接打开并截断目标的做法。合成测试已复现旧 Windows 分支会写穿文件符号链接，并验证修复后拒绝该路径；另覆盖写入／同步／关闭／发布失败保留原件、撤权、目标变化、父目录链接重定向和本应用并发保存。

覆盖用 `rename` 替换目录项，新建用硬链接原子发布；不支持硬链接的文件系统会失败，不回退为不安全覆盖。临时文件位于目标目录的 `.pinekin-export-*` 中；关闭写句柄后不比较跨关闭的时间戳，而是检查身份／长度并限量逐字节回读，拒绝同长度内容篡改。清理前检查父目录、临时目录和本次文件身份，只删除匹配的文件和空目录，不递归删除；目录或文件被替换时保留并警告，不扫描移动后的路径。清理失败或异常退出可能残留明文。Windows ACL、硬链接、文件占用及网络盘行为尚需原生验收。发布与清理均不承诺抵御最后身份检查后的恶意路径替换，详见 [接续文件安全边界](context-handoff.md#资源与隐私)。

## 构建与自动验证

在 Windows 原生环境、仓库根目录执行：

```powershell
npm ci
npm run test:coverage
npm run build
node scripts/build-engine.mjs
npm run test:e2e
npm run dist:win
```

`dist:win` 先做类型检查和生产构建，再生成 x64 NSIS 安装包至 `release/`；现有多尺寸 ICO 直接复用，不要求运行 macOS 图标生成工具。Engine 使用当前 Node 运行已安装 TypeScript 的 JS CLI，不执行 Unix `.bin/tsc` shim。

GitHub Actions 配置 `macos-latest` / `windows-latest` 矩阵，在各平台执行覆盖率、生产构建、Engine 构建和桌面 E2E；Windows job 随后打包并上传 NSIS 测试安装包。两个系统的诊断附件分开命名。没有触发／查看成功的 Windows 运行前，不能把配置存在当作 CI 已通过。

执行预算按层级区分：CI 中 Playwright 全局 25 分钟、E2E 步骤 28 分钟、整个 job 40 分钟；单用例仍为 30 秒，保持串行、不增加重试、不忽略失败。全局预算依据 Windows 已运行 12.9 分钟只执行至第 68 / 106 项的实际记录设置，用于让套件完成或先由 Playwright 结束并写出报告，不代表已解决单项超时。始终生成 `test-results/e2e-report.json`，诊断上传使用 `always()` 并限时 3 分钟；`desktop.spec.ts` 对手工创建的 Electron context 显式采集 CI trace，失败时保留 `trace.zip`。只包含隔离合成数据；其他 spec 尚未统一采集 trace。步骤失败或取消会尝试上传现有结果，但 runner 丢失／强制结束整个 job 时不保证能执行收尾。安装包仍受成功门禁约束，不因诊断上传成功而视为通过。

锁文件必须包含打包器的跨平台 peer 依赖，包括 NSIS 未直接使用、但 `app-builder-lib` 声明的 `electron-builder-squirrel-windows`。开发机若设置了 `legacy-peer-deps=true`，不能据本地安装成功判断干净 CI 可安装；修复锁文件可用 `npm install --package-lock-only --ignore-scripts --legacy-peer-deps=false`，不修改全局设置或现有 `node_modules`。用 `npm ci --dry-run --ignore-scripts --legacy-peer-deps=false` 检查依赖解析；这只是安装计划验证，不代替云端实际安装、生命周期脚本和测试。

通用日志测试在 Windows 继续运行；实际依赖 macOS 沙箱 SQLite、应用包识别或 Unix 权限的成功测试按能力限定平台，不将整个 Windows 套件跳过。未实现能力应验证明确拒绝且无副作用。桌面自动测试仅使用合成数据、隔离 userData、剪贴板替身和文件框替身。

**本地桌面验证约束：** E2E 会启动额外 Electron。用户要求只复用主 dev、不重启、不抢焦点时，不自动运行这些测试；记录未运行原因。CI 配置不意味着获准在用户电脑启动副本。

## 没有本地 Windows 电脑时

1. 在当前开发机修复可复现缺陷并完成最小回归、类型检查、覆盖率和构建；模拟 Windows 的测试不算原生验收。
2. 经授权提交并推送，触发上述 GitHub Actions Windows job。检查各步骤真实结果及失败附件，按日志修复；未执行、不支持或跳过的能力不能标为通过。仅使用合成夹具，不上传真实会话或凭据。
3. Windows job 完整成功后，下载 `pinekin-windows-x64-test-installer` 测试包。托管 runner 是 Windows 环境，但通常使用 Windows Server 镜像，不能等同于 Windows 10／11 桌面验收。
4. 通过获授权的远程 Windows 桌面、虚拟机或 Windows 测试用户补齐下方交互清单。Apple Silicon 上的 Windows ARM 虚拟机运行 x64 包涉及模拟执行，应单独记录系统与架构，不能替代原生 x64 结果。

没有交互验收环境时，最多标为「Windows 自动化验证通过、安装与桌面交互待验收」，且必须以实际成功的 CI 运行作为依据；暂不宣称正式支持。远端 CI 启动 Electron 不授权在本地另起客户端。

## 安装包与签名

本批提供的是测试包构建入口，不是正式签名分发流程。CI 关闭证书自动发现，不配置或读取签名凭据；不要宣称包已签名、已公证、不会触发 SmartScreen，或已通过企业分发要求。正式分发前须另行确定证书／签名服务、时间戳、缺少签名时失败的门禁，以及最终产物验签。

本批 CI 测试运行生产构建中的应用，不运行 NSIS 安装／升级／卸载生命周期；安装成功和安装后启动必须另外验收。

## 待完成的 Windows 验收

以下全部为待验收项，不由 macOS、模拟 `platform: 'win32'` 或构建成功替代：

- 普通用户安装、安装后启动、重复启动；升级保留连接配置；卸载行为与协议关联。
- 合成日志连接、列表、搜索、长正文分页、刷新、断开；保存完整历史，文件内容和消息数量核对；取消／覆盖失败不虚报成功。
- 含中文／空格用户名、盘符大小写、跨盘、长路径；明确 UNC 支持边界。
- NTFS junction／符号链接、文件替换、来源活跃追加、读取权限不足、文件占用与原子替换失败。
- 125%／150%／200% 缩放、最大化、贴靠、多显示器、输入法、长提示与弹窗布局。
- Pinekin 深链冷启动／运行中投递；外部「查看原会话」须验证目标 App 真的选中正确会话。当前部分解析仍依赖 macOS 应用包，不承诺 Windows 客户端关联已实现。
- 保存文件上传目标 App 后被正确解析，并能继续下一轮对话；系统保存成功不等于目标已接收。
