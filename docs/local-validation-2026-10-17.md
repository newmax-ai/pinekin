# 获授权本机只读核验与格式修正

日期：2026-10-17。前一批 Codex legacy 适配已按授权提交为 `54d4780`；以下为随后基于本机结构发现完成的修正，本批未自动提交或推送。

## 授权与隐私边界

用户本轮明确授权查看本机客户端数据。只对 Codex 标准活动/归档日志目录做有界元数据统计和少量结构抽样，不扩展到整个主目录或无关文件；不读取凭据，不修改来源文件、外部数据库或客户端状态。

真实日志仅在生产解析器的独立只读调用中短时解码；没有运行真实会话，没有将其传入 Vitest / E2E，没有调用 `ImportCoordinator.commit` 或写入 Staithe 档案库。只输出结构、计数、版本声明和安全错误类别，不回显正文。

本仓库不保存真实样本、会话 ID、文件名、散列、私人绝对路径或原始内容。回归夹具均独立手写，仅模拟观察到的结构。以下是匿名汇总，不作为自动扫描授权，也不扩展未来任务的权限。

## 发现

1. 本机 Codex 日志以 `.jsonl.zst` 压缩形式为主，少量明文日志也声明 `history_mode=paginated`。原先 legacy-only 的合成验证不能代表本机可用性。
2. 部分分页主会话没有外部历史引用，根会话 ID 一致，所有记录 ordinal 从 0 连续；可在不读取其他文件的前提下做单文件文本投影。
3. 大量子会话包含 parent/session/subagent 边界，部分文件的压缩前或展开后大小超过当前预算。不能只删除校验来宣称兼容。
4. Cindy 安装元数据确认版本 0.1.97；只查看安装包元信息与指定数据目录顶层的文件元数据，没有打开其数据库或认证文件。目录顶层没有取得分享包，不代表整个机器没有导出文件，也不能据此宣布实际 `.cshare` 兼容。

## 实现修正

- `codex-rollout` 适配器版本升为 `0.2.0`。
- 新增 `src/main/codex-zstd.ts`：按标准 Zstandard 魔数识别，仅展开 Codex rollout，不递归处理其他压缩或档案格式。
- 原始输入和展开内容分别限制 5 MiB；使用原生异步解码，最大窗口 8 MiB，拒绝损坏、截断、尾随垃圾和不支持的字典。
- 新支持无引用、无子会话边界且 ordinal 从 0 连续的 paginated 主会话。缺失、重复、乱序或非零起点仍拒绝；不重建分页运行状态或当前有效分支。
- 继续拒绝历史继承、fork、子会话、未知记录和资源超限；不去补读关联文件。
- 文件选择框加入 `.zst`；压缩原件按精确字节保存和去重，不用展开结果替换原件。
- 无新第三方依赖。原生 Zstandard API 要求 Node.js 22.15+，已同步 package.json / lockfile 的根项目 engines；本轮实际使用 Node.js 24.22.0，并单独验收 Electron 路径。

**没有将这 3 份真实日志导入 Staithe，也没有进行原生恢复。** 本轮是只读格式核验。UI 中的能力等级仍保留为 fixture-tested：自动化测试使用合成数据，不能因几个文件成功就提升为所有客户端集成验收通过。
