# 通用接续文件

更新：2026-10-23。

## 产品边界

macOS 默认路径为 **选择来源会话 → 点击「复制接续文件」→ 在支持文件粘贴的 App 中添加附件**。Windows／Linux 主按钮为 **保存接续文件**，保存完整 Markdown 后由用户手动上传或拖入目标 App，不调用未支持的文件剪贴板。

不选择目标 App，不弹预览或交接说明面板，不检查目标连接、启动位置或会话创建 API，不打开其他 App，不自动新建对话、粘贴或发送。复制对象是 Markdown **文件本身**，不是正文、路径文字或深度链接。

「更多 → 保存完整接续文件」使用系统保存框导出同一种完整通用 Markdown，适用于手动上传或拖入文件；Windows／Linux 页头主按钮复用该流程。原会话打开、当前片段复制／导出和旧档案入口保留；Codex／NewMax 原生迁移仍在「更多 → 原生历史迁移（高级）」中独立提供，能力边界不变，确认没有已接入目标时隐藏迁移与目标设置入口。

文件是可核对的文本上下文，不是智能摘要、原生恢复或已核实的任务简报；附件、工具结果、运行状态、模型配置与权限不迁移。引用分隔和安全说明不构成任意提示注入防护保证。目标未真正接收文件之前，不宣称已接续。

## 与导出聊天记录的区别

两者都保存为 `.md`，菜单按用途而非格式命名：

- **导出聊天记录**：只导出当前界面已读取的文本，不补读其他片段；存在分段时显示 **导出当前片段**。
- **保存完整接续文件**：重新读取完整可读历史，并附上接续说明、来源快照、生成时间、消息编号和权限边界；与顶部 **复制接续文件** 的内容类型相同，仅交付方式不同。

“完整”仅指完整可读文本投影，不表示包含原生会话全部记录、附件或工具运行状态。两种文件都不是原生会话恢复，也不是智能摘要。

## 默认流程

以下文件剪贴板步骤适用于 macOS；Windows／Linux 点击「保存接续文件」时，在同样准备与复核令牌后打开系统保存框，不创建剪贴板副本，不调用文件剪贴板。保存取消或失败仍释放令牌，不显示成功。

1. 用户点击「复制接续文件」。按钮文案和位置不变，忙碌期间禁用重复操作。
2. `SourceBrowser.transfer()` 从零读取已授权来源的完整可读快照，合并跨页长消息和读取说明，不使用 renderer 当前分页。不沿历史路径补读文件；来源改变则拒绝混合版本。
3. `buildHandoff()` 生成不含目标字段的 `pinekin.handoff` v2 与 UTF-8 Markdown。renderer 只获得 UUID 令牌，不获得全文、预览或文件路径。
4. 若准备期间切换会话、禁用或卸载界面，迟到令牌只释放，不交付。正常情况下自动继续本次点击所授权的文件复制，无需二次按钮确认。
5. 主进程复核授权，写入自身数据目录中的私有 `.md` 副本并完成落盘，再写入文件剪贴板。
6. 成功后原按钮显示「已复制」3 秒，使用原文案隐藏占位保持按钮宽高；同时在消息区顶部居中的共享 Toast 提示「文件已复制」，保存文件时提示「文件已保存」。Toast 与正文更新提示复用同一组件和浮层，反馈收起后恢复待处理更新。不声称目标收到附件或模型已读取；失败显示具体错误，不显示已复制，也不静默退回文字复制或原生迁移。
7. 无论交付成功、失败或取消，界面释放内存令牌。文件副本不能随令牌释放、页面关闭或新一次复制立即删除，否则尚未粘贴的文件会失效。

没有常驻目标列表、预览、读取说明列表、技术统计或「重新准备」。详细读取说明保留在文件中；原附件需另行添加的提醒放在按钮提示中。

## 文件结构

`pinekin.handoff` v2 与旧 `staithe.session` 档案包分离：

- `source`：来源 App、opaque 条目 ID 和读取快照。
- `createdAt`：生成时间，不声称交付时仍为来源最新状态。
- `coverage`：完整可读文本投影范围、消息数和来源窗口消息数，不等于原生全部记录数量。
- `messages`：`user/assistant`、原文和快照内的 `m1/m2/...` 引用编号，不冒充原生消息 ID。
- `warnings`：分页读取说明去重后的集合，包括附件与上下文损失。

**移除 `target` 字段和「目标：App 名称」**，不为不同 App 生成不同正文。Markdown 中每条正文以 JSON 字符串引用，保留空白、换行、Unicode 和角色边界；不执行历史命令。内部结构不是目标必须安装插件才能理解的私有导入协议。

## 文件剪贴板与系统范围

- 本次实现 macOS 文件复制：使用安装的 Electron 44 `ClipboardItem`／`clipboard.write()`，通过 `electron application/osclipboard;format="public.file-url"` 写原生文件 URL。
- URL 由 Node `pathToFileURL()` 编码空格、Unicode、`#`、`%` 等，不写 `text/plain`，也不把路径当成用户要复制的正文。
- Windows／Linux 文件剪贴板暂未实现：主按钮直接走「保存接续文件」，更多菜单也保留保存入口；底层若收到 `copy-file` 仍明确拒绝，不猜测平台格式或宣称全平台可用。取消保存不显示成功；成功仅表示文件已保存。
- 接收端必须支持文件粘贴和 Markdown 附件。目标接收能力、解析范围和模型上下文仍需分别验证；文件复制成功不是目标接续成功。
- 原来的 `resolveHandoffLaunch`、默认目标能力枚举和复制并打开分支已移除。高级原生目标注册表不受影响。

## 资源与隐私

- 原始读取预算沿用 32 MiB／100000 条文字，读取说明最多 1 MiB；超限失败，不截断。
- 完整 Markdown 最多 64 MiB。移除旧的 1 MiB **文字**剪贴板预算，文件剪贴板只携带文件引用，不受该旧预算限制；64 MiB 也不是目标模型的上下文上限。
- 仅明确复制时在 `userData/clipboard-handoffs/pinekin-handoff-<UUID>.md` 创建明文副本，目录 `0700`、文件 `0600`，不包含用户标题等不可信路径片段。
- 目录拒绝符号链接、非普通文件；新文件使用独占创建。落盘或剪贴板失败仅尽力删除本次副本，不删除原件或其他副本。
- 副本累计上限 256 MiB／1024 个条目；到达预算后提示保存到自选位置，不自动删除可能仍在剪贴板中被引用的文件。成功副本持续保留，不会因为退出 Pinekin、断开来源、下一次复制或令牌过期而删除；不用时可在上述目录中手动删除，删除后旧剪贴板引用将失效。暂不提供自动清理或应用内清理入口。
- 准备正文同时只保留一个，令牌 5 分钟有效；重载、关闭窗口、显式释放清空内存。准备期间不自动落盘。
- 每次交付和保存框返回后复核来源授权；不读取目标凭据或设置，不写外部数据库。
- 导出路径只来自系统保存框，必须为绝对路径且扩展名为 `.md`；初次检查与发布前检查均拒绝最终符号链接、悬空链接及非普通文件。保存文件由用户管理。
- 完整接续文件与「导出聊天记录」共用 `save-markdown.ts`：在目标父目录的 `.pinekin-export-*` 临时目录中独占创建文件，完整写入、同步、关闭后复核授权、父目录解析／身份及目标快照，再发布；不直接打开或截断旧文件。写入、同步、关闭或发布失败不改旧文件，不回退为直接覆盖。
- 覆盖使用同目录 `rename` 替换目录项，不写穿最终符号链接或修改旧文件的其他硬链接；新建使用硬链接原子发布，目标已被占用则失败，不覆盖竞争者。文件系统不支持硬链接时明确失败；FAT／exFAT、网络盘等不能据此宣称已支持。
- 临时内容为明文，Unix 文件权限为 `0600`，Windows 依赖目标文件系统 ACL，不把 POSIX mode 当作 Windows 权限保证。正常结束清理临时目录；清理失败记录警告、不掩盖原始错误或把已发布文件报告为保存失败，异常退出可能残留 `.pinekin-export-*`。
- 该实现检查准备期间可检测的路径变化，且最终文件替换不会沿文件链接写入；Node 未提供跨平台的目录句柄相对发布或条件替换 API，因此不承诺抵御最后检查后恶意替换整个父目录／已有目标的并发进程，也不承诺断电后的目录项持久性。Windows 原生文件系统行为仍待实机验收。
- 剪贴板与本地副本不是加密存储。不会自动脱敏或上传；在目标中发送文件遵循目标的数据规则。

## IPC

新接口位于 `window.staithe.sourceActions`，与旧文本交接通道隔离，避免旧 preload 被误当成文件复制：

| 方法 | 通道 | 参数 |
| --- | --- | --- |
| `prepareHandoffFile` | `pinekin:handoff-file-prepare` | 来源 opaque ID |
| `deliverHandoffFile` | `pinekin:handoff-file-deliver` | UUID + `copy-file / export` |
| `discardHandoffFile` | `pinekin:handoff-file-discard` | UUID |

不再注册默认 `handoffTargets`；旧 `copy / copy-open` 动作拒绝。IPC 校验参数数量、主窗口和顶层 frame，服务验证 ID、UUID 与动作。renderer 不传正文、任意 URL、命令、目标名称或文件路径。准备与交付互斥；文件写入后、剪贴板提交前再次执行授权和令牌校验。

结果仅为 `file-copied`、`exported`、`cancelled`，不包含 `app` 或 `launch`。旧主进程／preload 未加载新接口时提示用户在方便时更新主实例，不自行重启或降级。

## 验证边界

自动回归使用合成来源、临时目录和剪贴板替身，覆盖：完整历史、特殊字符、超过旧文本预算、文件持久保留、受限权限、失败清理、存储预算、撤权、过期、重载、非法 IPC、界面过时请求、无目标的一次点击复制及明确保存。

桌面 E2E 已改为替换 `clipboard.write()` 和系统文件框，在隔离 userData 中检查原生文件格式及实际 `.md` 内容。运行会额外启动 Electron；未经当次授权不执行，不把自动回归、类型检查或构建冒充真实 App 附件粘贴验收。
