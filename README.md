# Pinekin

**换个地方，继续思考。**

Pinekin 是独立、本地优先的跨 App 会话中转桌面项目，归属 `newmax-ai`。主流程是 **连接来源 → 浏览和查找 → 按需读取 → 在支持的目标中接续**，不是先把所有对话复制进档案库。

> 当前已实现来源直读与独立的档案兼容入口。**目标端自动创建、打开与接续尚未完成，所有自动接续按钮均禁用。** 不把复制文本、导出文件或读取正文成功称为“一键同步成功”。本轮只用合成数据验证，不代表所有第三方客户端版本都兼容。

原名 Staithe，仓库与本地目录暂不改名。品牌使用 Pinekin，安装身份与历史数据格式保持兼容，不耦合修改 NewMax 主仓库。

## 现在怎么用

1. 打开 Pinekin，侧栏 **会话来源** 只显示已保存连接的 App；未连接时保留 **所有会话**，不把支持的 App 当作会话来源占位。
2. 点击侧栏 **连接 App**，勾选一个或多个 App，再点 **连接所选 App** 批量添加；打开弹窗、勾选时都不扫描。NewMax 自动查找 `~/.newmax/newmax.db`，支持当前进程继承的绝对目录 `NEWMAX_USER_DATA_DIR`；Codex 当前／归档目录一并连接，Cindy 自动发现国内／国际版账号库。只检查确认过的固定位置，不搜遍磁盘。
3. 每个 App 单独检查连接和首次读取结果，单项失败不阻止其他 App。全部成功后单选进入对应来源，多选进入所有会话；有失败则保留逐项原因、重试所选项与自定义位置入口，也可先查看已连接会话。已授权 App 出现在侧栏；分页与搜索覆盖授权范围内全部已发现元数据，不再使用旧开发批次的 10 / 50 条上限。
4. 点击一条会话才完整解析正文。Claude Code 与 Codex 列表可用首条有效用户输入的首行短文本作为标题兜底；标题缺失时有上限地扩展头部预览，不加载整段历史。浏览器任务、子会话与已识别的纯辅助记录明确标识。浏览器任务优先展示任务文本，页面快照和已识别的 Claude 前置上下文可展开；工具调用／结果独立折叠展示并单独计数，不再把工具驱动日志简单表现为只有一句提问。Codex 来源阅读排除系统／开发者与已识别的注入上下文，旧档案导入规则不变。未支持、损坏、超限和子会话仍列出，正文能力与目录发现分开。
5. 点击原有 **Pin 走这段对话** 查看目标能力状态；当前明确显示未支持，不写入目标。**连接 App** 弹窗中的 **已有档案** 保留手动文本交接。
6. 启动后加载**已保存授权的位置**；切回窗口时后台检查，可见时每 60 秒兜底，隐藏／最小化时暂停定时检查。刷新保留当前选择、已加载范围和正文；向下翻找或操作列表时先提示 **列表有更新，点击查看**，搜索结果同样不突然换序。正文变化只提示 **此对话有更新 → 查看更新**，重读失败保留原文，删除则明确标注旧快照。列表标题栏 **刷新** 更新当前来源，阅读区 **重新读取正文** 只读当前会话；**连接 App → 管理连接** 可单独刷新、暂停或断开。未连接／已断开的 App 不会被检查或自动添加。

### 来源支持边界

| 来源 | 连接位置 | 会话目录 | 按需正文 |
| --- | --- | --- | --- |
| NewMax | `.newmax/newmax.db`、显式环境覆盖目录或手动指定数据库；支持默认／配置数据目录间的共享库链接 | `conversations` 全部行，包含隐私、分叉和空会话的元数据 | 与既有 1.1.22 白名单契约相容的普通主会话；隐私、分叉、非 App 会话仍不支持 |
| Claude Code | `projects` 或单项目日志目录 | 递归 `.jsonl`，子会话也列出 | 既有完整单根末条消息父链文本投影；逻辑父链、压缩和子会话有明确限制 |
| Codex | `sessions`、`archived_sessions` 或明确选定目录 | 递归 `.jsonl` / `.jsonl.zst` / `.jsonl.zstd` | 受支持的独立主会话；跨文件继承等格式仍有限制 |
| DeepSeek Harness | 明确选定的日志目录 | 同上 | v4 独立主会话文本投影，不是 DeepSeek 网页聊天 |
| Cindy | `Cindy` / `CindyGlobal` 下的 `cindy-*.db` 或手动指定数据库 | 经结构检查的 `sessions` 元数据 | **正文直读尚未验证，暂不启用**；已有快照／分享包的档案解析继续兼容 |

- “全部”指**用户授权位置中可访问、非符号链接的匹配日志或会话表行**，不是自动搜遍机器或账户。不同位置可能覆盖同一会话；不会擅自合并不同原件，数量是发现条目数。
- 统计完成才显示总数。未连接、加载中、部分可读、暂停和读取失败分别显示，不能冒充 `0`。待刷新仅保留为未启动扫描时的兼容状态，不是正常启动默认状态。不可访问子目录会标记统计不完整。
- Claude Code 日志列表先读取头、尾各至多 64 KiB，按**自定义标题 → 自动标题 → 摘要 → 首条有效用户文本 → 文件名**选名；同类取窗口中最后一条有效标题。Codex 未压缩日志从头部提取首条有效提问，不把系统／开发者、已识别的环境或 AGENTS 注入当标题，不读取来源根之外的标题索引。两者标题仍缺失时，将连续头部预览扩展至多 1 MiB；首问不从不连续尾部推断，显式标题最多 200 个 Unicode 字符，首问兜底只取有效首行、最多 80 字加省略号，浏览器任务先剥离明确的页面包装。大日志和子会话也提取标题，但不改变正文支持状态。其他日志保持前 64 KiB 策略，压缩文件在点击读取前仍使用文件名。按需读取成功后，解析出的标题同步到内存列表与搜索，保留原文件名查找，不重置分页或持久化正文。正文上限仍为 5 MiB，解压预算不变。**发现数量不受正文预算限制。**
- Codex 来源阅读仅展示可投影的问答：排除系统／开发者消息、完整的已知前置上下文包装；IDE 包装只在已知开头标记下提取实际请求，普通文本中的标签引用、代码示例、重复提问及未闭合／未知包装保留。读取报告列明省略数量；工具、推理和事件副本仍不伪装为助手答复。旧档案入口仍保留原系统历史投影，不将来源阅读等同于完整原生会话恢复。
- Claude 来源阅读兼容同一父链上连续且一致缺少 `apiBlockIndex` 的旧助手片段，保持独立片段，不猜测增量合并或去重；混合索引、倒序、缺失父链、多根及子会话仍拒绝。工具预览最多 100 条、每条 1,024 字符，总数和预览截断分别说明；附件不加载。长文字消息首屏至多 4,000 字符，可展开完整文本。原始文本仍留在来源文件，展示折叠不改写来源。
- 不沿日志里的路径、附件、父会话引用读取其他文件，不执行历史命令。日志中的符号链接不跟随并计数。NewMax 的已知数据库入口允许解析默认／配置数据目录内真实 `newmax.db` 的共享链接：保存并固定真实路径，之后刷新不跟随副本链接改指向；其他目标须手动选择实际数据库文件，数据库副文件链接仍拒绝。
- 当前搜索是元数据搜索，不是完整全文搜索；没有暗中建立正文副本。后台检查只复用内存元数据：未变日志只检查文件属性，SQLite 主文件及 WAL 等副文件未变时不启动查询，正文仍按需读取。自动检查至少间隔 15 秒，失败按 30 秒起、最高 5 分钟退避；手动刷新可立即重试，用户暂停的扫描不自动恢复。没有目录监听、逐字同步或双向写入。

## 数据与隐私

- 默认主入口不调用档案库 `list()`，空档案库也可以浏览来源。正文只在内存中按需展示，不保存原件，也不调用归档确认流程。
- 仅 `userData/connections.json` 持久化连接 ID、来源类型与规范化绝对位置；文件 `0600`、目录 `0700`，原子替换并串行修改。它是明文配置，不是加密库；Windows 权限语义不同。
- 断开连接撤销读取入口、清空内存目录；不会删除来源数据或已有档案。损坏配置报错，不静默覆盖。
- SQLite 直读目前仅验证 **macOS**：系统 `sandbox-exec` 强制禁止文件写入和网络，独立 `sqlite3` 进程用固定白名单 SQL、只读事务读取 DB 与已提交 WAL；不复制整库、不查询认证／设置表、不执行来源指令。活跃 WAL 不使用 `immutable` 忽略日志；只有无副文件的稳定库使用该模式，结束前再次核验文件身份和变化。读取组件不可用、活动回滚日志、读取层遇到的链接或不兼容结构均明确报错，不回退到可能写入来源的方式；**不要手动删除副文件**。Cindy 已授权但曾失败的连接可在管理连接中刷新。
- 未授权时不扫描真实客户端目录、主目录或凭据。选择框由主进程控制，renderer 不能传任意文件路径。
- 历史作为不可信文本与代码围栏展示，不渲染不可信 HTML、脚本、外部图片或工具调用。没有云上传、自动发送、自动摘要或自动脱敏。

## 已有档案（兼容入口）

历史功能保留在 **已有档案**，不与实时来源计数混合，也不自动删除已有 29 段或其他用户数据：

- 文件选择 → 只读预览 → 确认保存原件与文本档案；取消不落盘。
- Staithe v1/v2、Ember v1、NewMax 白名单快照、Claude Code JSONL、Cindy 未加密 v1 分享包及本地快照、Codex 日志、DeepSeek Harness v4 日志解析。
- 内容散列去重、损失报告、旧 `library.json` 读取，新原件和记录整体原子发布到 `imports/<sha256>/`。
- 导出文本包／Markdown／复制交接文本：都是**手动文本交接**，不是目标会话创建或原生恢复。
- 原有本地深链继续定位档案并切换兼容入口；不用于访问外部来源。
- `npm run import:local` 只保留为历史开发批次工具，默认预演、`--confirm` 才保存。它的批次上限不参与新的来源浏览。

具体格式、压缩预算和损失限制见 [档案格式](docs/import-formats.md)。原件、记录和连接配置均是本机明文；旧归档可能包含敏感内容，不能把保存成功当作已脱敏。

## 界面与安全

Electron + React + TypeScript 独立三栏工作台，复用本项目已有浅／深主题、品牌图标、Lucide、ScrollArea mask、Tooltip、连续圆角和可调宽侧栏。不依赖 NewMax 运行时。常规弹窗标题统一使用无装饰图标的 `DsDialogHeader`，关闭按钮由 `DsDialogClose` 统一规格；搜索框的功能图标保留。来源多选使用本地 `DsCheckbox`，对齐 NewMax 的圆形选框、加粗对勾、悬浮／按压与禁用反馈，保留 Pinekin 主题 token、整行点击及键盘操作，不使用系统原生方框。

来源逻辑接入原有设计，不另做视觉方案：保留顶部返回／前进与侧栏开关、Logo 右侧搜索图标、左下插画、紧凑卡片和阅读区样式。点击搜索图标或按 `Cmd+K` / `Ctrl+K` 打开原搜索弹窗；来源搜索仅更新弹层内结果、计数与分页，不改变底下的列表、滚动位置或当前正文；关闭或清空搜索不触发主列表重载，点击结果才切换会话。搜索弹窗保持 660 × 500px，窗口较小时按视口收紧；结果数量、分页、加载、无结果和错误只改变内部内容，不改变弹窗尺寸，结果在内部滚动。返回／前进恢复来源与实际打开的会话，搜索词不进入浏览历史。连接管理和已有档案收在 **连接 App** 弹窗内，不新增侧栏分组、品牌标签或常驻搜索框。连接弹窗保留无装饰图标的标题栏和品牌图标列表，支持多选后一次提交；不预先探测，提交才连接，处理过程中禁止重复提交。`ConnectSourcesDialog` 按列表顺序串行处理各 App，逐项显示进度与结果，不把首次扫描失败当作成功。失败项可重试或从详情指定位置，成功项不重复提交；部分成功时可先查看已连接会话。所有 App 都已连接时显示完成状态，仍可管理连接和打开已有档案。已授权但待刷新、部分可读或读取失败的来源仍保留在侧栏；断开最后一个位置才移除对应 App，并将失效的当前筛选及浏览历史恢复到所有会话。保留键盘操作与初始焦点，不引入宿主运行时。档案入口保留原有导入流程。

Electron 保留 `sandbox`、`contextIsolation`、具名 preload API、IPC 参数及顶层 frame 校验；拒绝任意导航、新窗口和权限请求。内部桥仍为 `window.staithe`，来源能力位于 `window.staithe.sources`，新增 `pinekin:sources-*` IPC，旧 `staithe:*` 接口不变。

空占位统一使用 `EmptyState` 与基于当前 app icon 松貂形象的六张线描 SVG。加载、统计、待刷新、暂停、部分可读、真正为空、搜索无结果、未选择、读取失败、格式未支持和无消息分别判断；只有完成统计才宣称来源为空。主阅读空区承载插画与单一行动，列表等小空间仅显示一句简短描述，不再叠加标题。主阅读区的大占位保留标题与一句简短场景描述：标题说明状态，描述补充原因／范围／能力，按钮表达动作，三者不互相复述；不重复展示本地读取／只读浏览等固定脚注。空占位整体弱强调：标题与描述直接使用全局 tertiary 及常规字重，全局三档文字共用主题基色（浅色黑、深色白），仅按 primary 88%／secondary 65%／tertiary 40% 的颜色 alpha 分级，不叠加元素 opacity 或空占位专用色阶，插画降低不透明度和饱和度，操作按钮统一使用 tertiary 样式；占位整体在所属空区的可用空间内水平、垂直居中，空间不足时可滚动。保留可读性与悬停／焦点反馈，不影响正常内容。原稿经生图后分格描摹为真实贝塞尔路径，支持深浅主题，运行时不加载原稿或请求生图服务。完整判定顺序、行动与资源路径见 [空占位规范](docs/empty-states.md)。

## 开发与验证

需要 Node.js 22.15+（建议与现有验收一致的 Node.js 24.22）和 npm。

```bash
npm ci
npm run dev
npm run test:coverage
npm run build
npm run test:e2e
```

测试先覆盖相关最小范围，然后 typecheck、覆盖率；IPC／桌面改动还需构建与 E2E。E2E 只使用合成数据、隔离 userData，替换文件选择框和系统剪贴板。`STAITHE_TEST_BACKGROUND=1` 使测试窗口从创建起隐藏、不聚焦；同时验证原生 show/focus 事件为空，不抢用户前台。正常主 dev 不使用测试标记。详见 [来源直读改造](docs/source-browser.md)。

## 兼容身份

- 显示名 Pinekin，包名 `@newmax-ai/pinekin`，安装身份 `ai.newmax.staithe` 保留。
- 默认 userData 沿用系统 appData 下的 `@newmax-ai/ember`，不自动搬迁。
- 开发隔离支持 `STAITHE_DATA_DIR`，兼容 `EMBER_DATA_DIR`，打包忽略二者。
- 文本包 `staithe.session` v1/v2，兼容 `ember.session` v1；深链 `newmax-staithe://session/<本地ID>`，兼容 `newmax-ember://`。开发模式不注册系统协议。
- 演示内容仅在测试夹具；旧演示档案不展示，也不自动删除。用户 ID、正文、标签不做品牌替换。
