# Pinekin

**换个地方，继续思考。**

Pinekin 是独立、本地优先的跨 App 会话中转桌面项目，归属 `newmax-ai`。主流程是 **连接来源 → 浏览和查找 → 按需读取 → 在支持的目标中接续**，不是先把所有对话复制进档案库。

> 默认 **复制接续文件**：从已授权来源读取完整可读历史，保留角色、原文、快照与读取说明，生成不绑定目标 App 的通用 Markdown，并复制**文件本身**。不选目标、不弹预览、不打开其他 App；用户在支持文件粘贴的 App 中添加附件。文件复制目前实现 macOS；其它系统可通过「更多 → 保存接续文件」导出。不自动新建、发送或生成智能摘要，也不把剪贴板写入当成已接续。原生迁移保留为高级入口。详见 [通用接续文件](docs/context-handoff.md)；真实跨 App 文件粘贴仍待验收。

原名 Staithe，GitHub 仓库现为 `newmax-ai/pinekin`，本地项目目录为 `pinekin`。品牌使用 Pinekin，安装身份与历史数据格式保持兼容，不耦合修改 NewMax 主仓库。

## 现在怎么用

1. 打开 Pinekin，侧栏 **会话来源** 只显示已保存连接的 App；未连接时保留 **所有会话**，不把支持的 App 当作会话来源占位。
2. 点击侧栏 **连接 App**，打开卡片右上角开关即连接，关闭即撤销该 App 的全部位置；不删除原会话。仅打开弹窗不扫描。NewMax 自动查找 `~/.newmax/newmax.db`，支持当前进程继承的绝对目录 `NEWMAX_USER_DATA_DIR`；Codex 普通／归档目录一并连接，Cindy 自动发现国内／国际版账号库。只检查确认过的固定位置，不搜遍磁盘。
3. 开关即时生效，连接后弹窗保持打开，点击 **完成** 才进入本次连接的来源；本次连接多个 App 时进入所有会话。未安装或没有本机会话属于正常状态，仅显示中性提示并保留自定义位置入口，不显示红色错误或计入失败汇总；权限不足、格式损坏等真正失败仍保留具体错误，未授权时可再次打开开关重试；已授权但读取失败时开关保持开启，卡片直接显示原因与自定义位置入口；需要刷新时使用主列表刷新入口。多位置断开中途失败保留剩余授权，不假装已关闭。分页与搜索覆盖授权范围内全部已发现元数据，不再使用旧开发批次的 10 / 50 条上限。
4. 点击一条会话才按需解析正文。NewMax、Cindy、Claude Code、Codex、DeepSeek Harness、WorkBuddy、Qwen Code 均按有界窗口阅读，超过旧 5 MiB 或 10,000 条消息不会因此被过滤；正文可用「上一段／下一段」继续阅读，界面区分来源消息总数与当前片段文本数。日志先流式检查完整结构，再只保留当前片段，不一次性聚合整份正文。Claude Code 与 Codex 列表可用首条有效用户输入的首行短文本作为标题兜底；标题缺失时有上限地扩展头部预览。较大 Claude 日志或归属仍未确定时，在发布目录前流式检查来源字段，不生成正文投影；UTF-8 BOM 不再漏过 SDK 来源判断。浏览器任务、子会话与已识别的纯辅助记录明确标识，工具活动独立展示并计数。Codex 来源阅读仍排除系统／开发者与已识别的注入上下文。仅已明确不支持的格式／会话边界、纯辅助记录从列表、搜索和计数中过滤；权限、暂时读取失败、损坏和单次工作预算耗尽均保留重试。旧档案导入规则不变。
5. 来源详情以标题为主，不再显示「来源直读」标签；小号操作靠右，窄窗口自然另起一行。**在原 App 打开** 仅在 NewMax／Codex 的原始 ID、记录类型及系统协议关联符合白名单时显示，点击直接发送定位请求；macOS 的 NewMax 正式版与专属开发包按 bundle 身份识别，不依赖 `Electron.app` 或可变显示名，也不会放行通用 Electron。多个开发副本并存时，需确认系统协议指向实际使用的实例。不可用时不留禁用按钮，原因在「更多」中查看。**复制接续文件** 一次点击即读取完整可读历史并复制通用 `.md` 文件，不再选择目标或弹出面板，也不自动打开 App。正文不含目标名称，详细读取说明保留在文件里；原附件需另行添加，不把助手历史声明当成已验证结论。忙碌期间保持按钮文案与位置，准备中切换来源则丢弃迟到结果，不复制旧会话。**更多 → 保存接续文件** 导出同一种完整文件，便于手动上传或拖入。文件上限 64 MiB，复制文件不受旧 1 MiB 文本剪贴板预算限制；不静默截断，也不把文件预算等同模型上下文。具体规则见 [通用接续文件](docs/context-handoff.md)。**更多 → 原生历史迁移（高级）** 保留 Codex／NewMax 原有创建、项目／工作区选择、回读、幂等和失败回滚机制，但不再是默认路径；目标设置仍位于更多菜单。其能力边界与未通过的现场验收不因新流程而改变，详见 [原生目标机制](docs/native-targets.md)、[NewMax 正式接续](docs/newmax-target.md) 和 [已有项目列表](docs/codex-project-catalog.md)。**更多**中可直接复制文本或导出 Markdown，不再弹出任务表单、预览确认或敏感内容复选框。复制／导出包含当前已读文本，不只取末尾 10 条；有分段时明确显示「复制当前片段／导出当前片段」，保留位置和快照说明，不冒充全会话迁移。原会话定位与跨 App 创建的边界见 [目标能力](docs/target-capabilities.md)。**连接 App** 仅管理来源；历史档案仍通过旧本地链接兼容访问。
6. 启动后加载**已保存授权的位置**；切回窗口时后台检查，可见时每 60 秒兜底，隐藏／最小化时暂停定时检查。刷新保留当前选择、已加载范围和正文；向下翻找或操作列表时先提示 **列表有更新，点击查看**，搜索结果同样不突然换序。后台发现正文变化以统一 Toast 提示 **此对话有更新**，右侧显示关闭按钮，不自动移动阅读位置；关闭只隐藏本次版本提示，不读取正文，同版本后台检查不重复弹出，后续新版本仍会提示。重读失败保留原文并就地提供 **重试读取**，删除则明确标注旧快照。列表标题栏 **刷新** 同时检查当前来源并重读当前打开的会话，保留阅读位置，即使目录版本未变也重读；来源详情不再保留底部刷新按钮或底栏；**连接 App** 弹窗打开期间暂停自动检查，已有后台检查不会禁用开关、完成或关闭按钮，也不发布迟到统计和错误；仅用户主动操作进入忙碌状态，关闭后恢复正常自动检查。弹窗在同一网格展示所有 App，不再使用国内／国际筛选；标题描述紧跟标题，每个 App 一张紧凑卡片，不区分「已连接／添加来源」两组；同一 App 的多个位置合并显示会话数，以 **small 开关**统一管理授权，开启即表示连接，不再重复显示连接状态标签；位置统计直接整合在卡片中，不再提供折叠详情或逐位置按钮。Codex 用「普通会话／归档会话」标明两类数量。卡片不设最小高度，不再预留大块空白，所有行继续按最大内容统一等高。正在连接、断开或等待选择位置的状态只替换当前卡片的 22px 数量行，完成后恢复统计，错误与正常提示也留在对应卡片；列表上方不再显示状态或预留反馈槽。未找到会话的提示直接替换卡片原描述，不与“自动查找本机会话”叠加，长提示可自然换行并保留自定义位置按钮。连接弹窗按真实内容自然增高或缩小，不预设大外框；高度变化使用 180ms 过渡，仅超过视口时限高并内部滚动，减少动态效果时禁用过渡。宽窗口三列，窄窗口自动收拢为两列或单列，不再打开独立的管理弹窗。未连接／已断开的 App 不会被检查或自动添加。

侧栏展开／收起沿用 NewMax 的 500ms 无回弹 spring 动画与专用开关图标，文字保持固定宽度并淡入淡出，不随侧栏挤压。收起保留已调宽度、筛选和阅读位置；系统启用“减少动态效果”时立即到位，动画中途更改也生效。

会话列表选中定位使用平滑滚动，让整张卡片避开上下 48px 渐隐区域；底部有更新提示时避开 96px 遮罩。系统启用“减少动态效果”时立即定位。连续切换会话时以最新选中项为准，不干扰普通手动浏览；来源会话与本地档案共用此行为。

来源会话切换使用仅作用于阅读区的淡出／淡入：旧画面 90ms 淡出，新画面延迟 40ms 后以 160ms 淡入；正文较晚返回时单独淡入，短暂读取不闪现整屏加载占位。页头、按钮和元信息保持原节点，不复制可交互的旧会话，不通过位移或缩放掩盖跳动。列表点击、搜索选择及返回／前进共用同一过渡，快速切换以最后目标为准；减少动态效果、后台窗口或不支持原生 View Transition 时直接切换。主 dev 视觉效果仍需现场验收，单元测试不等同实机确认。

### 客户端来源与执行内核

**先隔离客户端数据目录，再检查日志结构。** 当前用户的 `~/.newmax` 和显式 `NEWMAX_USER_DATA_DIR` 是 NewMax 数据根，不能连接为 Claude Code；其子目录也同样拒绝。从 NewMax 终端继承的 `CLAUDE_CONFIG_DIR` 若落入这些数据根，Claude 自动定位改用 `~/.claude/projects`，正常的 Claude 自定义绝对目录继续保留。旧错误连接启动时明确报告目录不匹配，不扫描成“0 条成功”；用户显式重新连接到有效 Claude 位置后才修复旧授权，保留连接 ID、去重并保留其他来源，正确目录缺失时不覆盖配置。

**NewMax 是来源 App，Claude Agent SDK 是执行内核；同为 Claude JSONL 格式不表示会话属于 Claude Code。** Claude 目录按连续头部中最早有效的用户／助手来源字段判断：明确 `entrypoint=cli/claude-desktop` 优先于同条 `promptSource=sdk`；通用 `sdk-*`／SDK 来源的执行日志不进入 Claude Code 列表、搜索与数量，也不直接冒充 NewMax 会话。续聊入口不覆盖原始归属，元数据、注入和旁支不改变主线来源；完整独立子链才可用自身入口。正文里的 App 名、路径、任务文字和工具名都不用于猜来源。

Claude 的 `mode`、`permission-mode`、`atis-latch` 等已知设置记录只作元数据跳过，不作为聊天节点、消息或工具活动，不应用其中的权限设置。完整日志若只有已验证的单根 `system/local_command` 父链，或整条由 `<bash-input>`、`<bash-stdout>`、`<bash-stderr>` 等已知本地命令包装组成的 `user` 记录与元数据，按纯辅助记录从列表、搜索和计数排除；本地命令混有真实问答时保留对话，命令及输出不进入正文、标题兜底、消息数或文本接续。普通提问里的标签引用、代码示例、未闭合标签、未知块和带真实请求的混合内容继续保留。未知类型、坏父链和混合会话不当作纯辅助记录隐藏，仍保留诊断。

NewMax 主会话继续从其已授权数据库读取，不把底层浏览器任务日志额外复制到 NewMax 或 Claude Code。未知 SDK 客户端不强行归属 NewMax；没有来源字段的旧日志按既有格式兼容，不能据此认证创建客户端。标题和初步来源预览最多扩展连续头部至 1 MiB，不从不连续尾部取原始入口。若此时仍无法确定归属，或 Claude 文件超过旧 5 MiB 边界，目录在发布条目前流式执行完整来源检查，只更新支持状态，不将预览之外的正文加入标题／搜索或缓存问答；文件变化或工作预算不足时保留可重试错误。较长的 SDK 独立子链不再等首次点击才过滤；未变文件继续复用元数据缓存。未支持的 Claude 压缩日志同样在目录阶段排除。来源在列出后变化而被过滤时，界面明确说明原因及原始文件未删除，不再静默清空；迟到检查不能覆盖新的读取。

### 来源支持边界

新增国内 Agent Harness 来源：**WorkBuddy、Qwen Code**，沿用同一连接开关、侧栏和分段阅读。WorkBuddy 按官方 5.8.3 macOS arm64 包核对，仅本地普通主会话；Qwen Code 按固定官方源码契约核对。两者不是 CodeBuddy、Claude Code 或 Gemini CLI 的别名，未验证的分叉／压缩／托管和原生恢复能力不会冒充支持。路径、证据及额外保守限制见 [国内来源契约](docs/domestic-sources.md)。

七种已连接来源共用**运行时上下文投影**：已知身份、环境、项目／IDE 等前置包装不进入默认问答、首问标题、复制导出和跨 App 接续；真实提问、字面引用、代码、未知格式与助手正文不按措辞猜测删除。数据库跨页前缀采用有界检查，无法确认完整边界时明确报错，不将残片带到目标。原件及旧档案导入语义不变，这不是任意提示注入的检测保证。见 [统一上下文规则与验收](docs/source-context-projection.md)。

| 来源 | 连接位置 | 会话目录 | 按需正文 |
| --- | --- | --- | --- |
| WorkBuddy | `.workbuddy/projects`、专属环境覆盖或单项目目录 | 浅层项目 JSONL；排除 cloud/subagents，同名侧车参与快照 | 本地普通主会话文本；辅助记录可缺 ID，支持相邻同 ID 的助手文字／工具／推理分块，正文按原顺序保留；分叉、压缩、重发回退及非相邻重复 ID 未支持 |
| Qwen Code | `.qwen/projects`、runtime/home 覆盖、单项目或 chats | 仅固定 `chats/*.jsonl`，完整检查已知边界 | 独立主会话单根父链文本；分叉、子会话、回退、压缩及托管历史未支持 |
| NewMax | `.newmax/newmax.db`、显式环境覆盖目录或手动指定数据库；支持默认／配置数据目录间的共享库链接 | 扫描 `conversations` 元数据，过滤已知不支持的隐私、分叉、非 App 和空会话 | 与既有 1.1.22 白名单契约相容的普通主会话；隐私、分叉、非 App 会话仍不支持 |
| Claude Code | `projects` 或单项目日志目录 | 递归 `.jsonl`，保留可读子会话；按完整内容排除纯任务流水、辅助元数据和无问答的本地命令日志，不按文件名封禁 | 当前文件完整单根末条消息父链；来源识别覆盖正文行预算，不因前置元数据超过 64 行误拒；不追读父文件，逻辑父链和压缩仍有限制 |
| Codex | `sessions`、`archived_sessions` 或明确选定目录 | 递归 `.jsonl` / `.jsonl.zst` / `.jsonl.zstd`；元数据 ID 冲突的条目在列表、搜索和计数中排除 | 当前文件内 ID 一致的主／子会话记录；明确说明继承上下文可能缺失，跨文件历史仍不追读 |
| DeepSeek Harness | 明确选定的日志目录 | 同上，压缩日志首次扫描即可提取标题 | v4 独立主会话文本投影，不是 DeepSeek 网页聊天 |
| Cindy | `Cindy` / `CindyGlobal` 下的 `cindy-*.db` 或手动指定数据库 | 经结构检查的 `sessions` 元数据 | 与已核对 0.1.110 字段契约相容的普通桌面会话当前问答；分叉、协作、远程及隐藏会话仍不支持；旧快照／分享包继续兼容 |

- “全部”指**用户授权位置中可访问、非符号链接的匹配日志或会话表行**，不是自动搜遍机器或账户。不同位置可能覆盖同一会话；不会擅自合并不同原件。显示数量是排除已知不支持后的条目数，不是原客户端所有记录总数；过滤不删除原件，来源变化后会重新判断。
- 统计完成才显示总数。未连接、加载中、部分可读、暂停和读取失败分别显示，不能冒充 `0`。待刷新仅保留为未启动扫描时的兼容状态，不是正常启动默认状态。不可访问子目录会标记统计不完整。
- Claude Code 日志列表先读取头、尾各至多 64 KiB，按**自定义标题 → 自动标题 → 摘要 → 首条有效用户文本 → 文件名**选名；同类取窗口中最后一条有效标题。Codex 未压缩日志从头部提取首条有效提问，不把系统／开发者、已识别的环境或 AGENTS 注入当标题，不读取来源根之外的标题索引。两者标题仍缺失时，将连续头部预览扩展至多 1 MiB；首问不从不连续尾部推断，显式标题最多 200 个 Unicode 字符，首问兜底只取有效首行、最多 80 字加省略号，浏览器任务先剥离明确的页面包装。大日志和子会话也提取标题，但不改变正文支持状态。DeepSeek 未压缩日志同样读取头尾标题并以真实用户首问兜底；Codex／DeepSeek 的 `.jsonl.zst/.zstd` 在首次扫描时流式解码，只保留标题、ID 和支持边界，等到严格 EOF 校验完成才发布结果。压缩输入及总展开量不再限 5 MiB，仍限制 8 MiB 解码窗口，拒绝损坏、截断与尾随垃圾，不递归解压或加载字典。按需读取成功后，Claude／Codex 仅用解析出的真实首问补齐文件名标题；已有标题保持不变，没有真实提问时保留原文件名，不用内部短 ID 降级覆盖。标题更新仅同步到内存列表与搜索，保留原文件名查找，不重置列表分页或持久化正文。日志每次阅读按块完整检查两遍，只保留轻量结构索引和当前片段；每次最多 100 条文字、每条 16,384 个 Unicode 码点。单行最多 8 MiB、结构索引记账最多 32 MiB、单次工作检查 30 秒，超出时报错并保留列表，不冒充任意大小均可读。
- Codex 来源阅读仅展示可投影的问答：排除系统／开发者消息、完整的已知前置上下文包装；IDE 包装只在已知开头标记下提取实际请求，普通文本中的标签引用、代码示例、重复提问及未闭合／未知包装保留。开头完整的 `recommended_plugins` 注入不进入问答或标题；完整的 `Files mentioned by the user / My request` 附件包装按真实请求取标题，文件说明与尾部图片占位默认折叠在「附件与上下文」，展开也仅显示普通文本，并明确附件预览未支持，不沿路径加载。「更多会话操作 → 读取说明」保留完整解析说明及省略数量，不再常驻报告横栏或显示说明计数；回退、上下文缺失等已知完整性问题直接在正文上方提示，读取失败、分段和附件提示仍就地展示。工具、推理和事件副本仍不伪装为助手答复。旧档案入口仍保留原系统历史投影，不将来源阅读等同于完整原生会话恢复。
- Claude 来源阅读允许同一父链、同一助手 ID 的递增追加块之间穿插纯 `tool_result` 用户记录；纯工具结果不算新一轮用户输入，工具前后的文字保持独立片段，不跨真实用户输入或其他助手 ID 续接。一致缺少 `apiBlockIndex` 的旧助手片段也保留独立片段，不猜测增量合并或去重；混合索引、重复索引、倒序、缺失父链及多根仍拒绝；独立子会话只读本文件可验证父链，原档案导入规则不放宽。浏览器任务包装支持 `http(s)://`、`file:///` 和 `about:blank`，这些地址仅作为文本识别，不导航或读文件。工具驱动记录默认展开活动目录，具体参数与结果仍按项折叠。工具预览最多 100 条、每条 1,024 字符，总数和预览截断分别说明；附件不加载。长文字消息首屏至多 4,000 字符，可展开已读片段，后续内容按段继续读取；片段可能切开 Markdown 结构，不把当前片段称为完整消息。原始文本仍留在来源文件，展示折叠不改写来源。
- 不沿日志里的路径、附件、父会话引用读取其他文件，不执行历史命令。日志中的符号链接不跟随并计数。NewMax 的已知数据库入口允许解析默认／配置数据目录内真实 `newmax.db` 的共享链接：保存并固定真实路径，之后刷新不跟随副本链接改指向；其他目标须手动选择实际数据库文件，数据库副文件链接仍拒绝。
- 当前搜索是元数据搜索，不是完整全文搜索；没有暗中建立正文副本。后台检查只复用内存元数据：未变日志只检查文件属性，SQLite 主文件及 WAL 等副文件未变时不启动查询，正文仍按需读取。自动检查至少间隔 15 秒，失败按 30 秒起、最高 5 分钟退避；手动刷新可立即重试，用户暂停的扫描不自动恢复。没有目录监听、逐字同步或双向写入。

## 数据与隐私

- 默认主入口不调用档案库 `list()`，空档案库也可以浏览来源。正文只在内存中按需展示，不保存原件，也不调用归档确认流程。
- 默认交接准备正文仅短暂留在内存，最多一个准备包，令牌 5 分钟有效；操作结束、重载或关闭窗口释放。用户点击复制后会在 `userData/clipboard-handoffs/` 保存明文 `.md` 副本，并向系统剪贴板写入文件引用。为保证随后粘贴可用，成功副本持续保留，不随断开来源或退出应用删除；累计上限 256 MiB／1024 个文件，超限提示显式保存到自选位置，不自动清理仍可能被引用的文件。文件 `0600`、目录 `0700`；文件复制目前只实现 macOS。系统剪贴板和文件副本都不是加密存储，不自动脱敏或上传。普通浏览仅以 `userData/connections.json` 持久化连接位置。用户主动执行高级原生迁移时，另存 `codex-target.json` 和 `codex-transfers/` 下的日志备份、事务状态及空工作区；只在授权的 Codex 数据根新增会话。文件 `0600`、目录 `0700`，备份是明文；界面不提供接续后撤销，创建失败时的安全回滚保留备份、不删除目标中的新增对话。它不是加密库，Windows 权限语义不同。
- 断开连接撤销读取入口、清空内存目录；不会删除来源数据或已有档案。损坏配置报错，不静默覆盖。
- SQLite 直读目前仅验证 **macOS**：系统 `sandbox-exec` 强制禁止文件写入和网络，独立 `sqlite3` 进程用固定白名单 SQL、只读事务读取 DB 与已提交 WAL；不复制整库、不查询认证／设置表、不执行来源指令。活跃 WAL 不使用 `immutable` 忽略日志；只有无副文件的稳定库使用该模式，结束前再次核验文件身份和变化。读取组件不可用、活动回滚日志、读取层遇到的链接或不兼容结构均明确报错，不回退到可能写入来源的方式；**不要手动删除副文件**。Cindy 已授权但曾失败的连接可在管理连接中刷新。
- 未授权时不扫描真实客户端目录、主目录或凭据。选择框由主进程控制，renderer 不能传任意文件路径。
- 历史使用安全 Markdown 展示：标题、段落、强调、列表、引用、代码、表格与删除线经 token 转为 React 白名单节点。HTML 显示源码文字，链接只显示标签、图片只显示替代文本，不生成导航或资源节点，不执行脚本或历史工具。没有云上传、自动发送、自动摘要或自动脱敏。
- Cindy 正文同一只读事务内检查普通 `desktop`、active/archived、无父／分叉、非远程／Orca／协作成员／隐藏边界，按 `created_at, rowid` 投影当前 user/assistant；过滤清空前和回退消息；NewMax／Cindy 正文每次最多读取 100 条、每条最多 16,384 个 Unicode 码点，长消息可从原位置继续读取，整段会话不再受旧 5 MiB／10,000 条上限过滤。窗口校验所选会话的完整文本投影指纹及会话状态，不再因同库其他会话写入或 WAL checkpoint 误报正文变化；所选正文（含未读尾部）或可读边界变化仍拒绝混合版本。指纹在同一只读事务中计算，只返回摘要与有界正文片段；目录扫描不新增正文读取。目录阶段先验证字段结构，并用与正文相同的会话／协作元数据条件判断是否支持，只返回标题、ID、时间与支持标记，不读取消息正文；字段缺失报连接错误，不伪装成空列表。`0.1.110-schema` 是字段契约标记，不代表每次探测安装版本。

## 已有档案（兼容入口）

历史功能保留在档案兼容界面，可通过旧本地深链访问；**连接 App** 弹窗不再提供「已有档案」按钮。不与实时来源计数混合，也不自动删除任何已有档案：

- 文件选择 → 只读预览 → 确认保存原件与文本档案；取消不落盘。
- Staithe v1/v2、Ember v1、NewMax 白名单快照、Claude Code JSONL、Cindy 未加密 v1 分享包及本地快照、Codex 日志、DeepSeek Harness v4 日志解析。
- 内容散列去重、损失报告、旧 `library.json` 读取，新原件和记录整体原子发布到 `imports/<sha256>/`。
- 导出文本包／Markdown／复制交接文本：都是**手动文本交接**，不是目标会话创建或原生恢复。
- 原有本地深链继续定位档案并切换兼容入口；不用于访问外部来源。
- `npm run import:local` 只保留为历史开发批次工具，默认预演、`--confirm` 才保存。它的批次上限不参与新的来源浏览。

具体格式、压缩预算和损失限制见 [档案格式](docs/import-formats.md)。原件、记录和连接配置均是本机明文；旧归档可能包含敏感内容，不能把保存成功当作已脱敏。

## 界面与安全

共享 `DsDialog` 默认支持点击外侧遮罩关闭，连接来源、管理连接、搜索、导入与交接弹窗一致生效。点击正文、内部留白或从内部拖到外侧不会误关；忙碌时仍禁止关闭，关闭后恢复触发位置的焦点。特殊流程可显式传入 `dismissOnBackdrop={false}` 禁用遮罩关闭。

弹窗统一轻微缩放并淡入淡出：180ms 从 97% 放大至原尺寸，140ms 缩小淡出，遮罩同步渐变，不改变布局。条件渲染的弹窗通过 `DsDialogPresence` 包裹整个条件表达式（含封装弹窗组件），业务状态立即关闭，原节点仅保留至退场结束；退场期间禁止交互，完成后恢复触发焦点，缺失动画事件时有兜底清理。系统启用“减少动态效果”时取消面板及遮罩动画，并立即卸载。

详情更多菜单通过本地 `DsMenu` 复用同一组设计系统缩放淡入淡出动画，以触发器左下方为锚点，退场立即禁止交互并在结束后卸载；减少动态效果、快速重开和事件丢失均有清理保护。Tooltip 在菜单展开期间及鼠标点击聚焦时被抑制，关闭菜单或设置面板返回焦点不会自动弹出提示，正常重新悬停和键盘聚焦仍可显示。

侧栏与会话栏均可拖动右边缘调整宽度，并分别记住本机设置；双击恢复默认，聚焦分隔线后可用左右方向键或 Home/End 调整。会话栏保留 310px／窄窗 280px 默认宽度，可在 240–560px 内调整，窗口空间不足时自动收紧，为阅读区保留空间；上下渐隐高亮沿用现有视觉。

来源会话与本地档案列表选中卡片时，只在必要时调整列表自身的滚动位置，让整张卡片避开上下 48px 渐隐区；底部有更新提示时避开 96px 遮罩，并预留末项所需的滚动空间。重复点击、键盘重新聚焦选中项、搜索选择与返回／前进均适用；已在安全区内不移动，常规重渲染不把手动滚动拉回，首尾到边界时使用原有遮罩关闭规则。

会话栏的已加载描述放在来源标题下方，保持 2px 紧凑间距；右侧使用本地 `DsRefreshButton`，对齐 NewMax 钱包的 hover 预备角与点击蓄力回弹曲线。加载使用 18 × 12px 的微型三点流动动画，三枚 3px 圆点依次围绕自身中心等比缩放（0.5–1.15 倍，占位直径 1.5px，峰值 3.45px），无位移、全程保持正圆，继承原文字颜色。每轮 1.2s，三点峰值按左→中→右相隔 180ms 依次接力；先放大提亮，再渐退为低亮尾迹，让右行方向更清楚。尾迹与下一轮衔接，整组不静止，不改变小圆点尺寸和中心缩放。来源扫描时原位替换侧栏右侧数量，其他已完成来源仍显示数字；完成后自动恢复数量，不改变行高。列表及搜索等待使用同一微型动画，扫描时保留已发现数量。长请求保留旋转忙碌反馈，减少动态效果时取消循环；不新增扫描或动画定时器。更新提示按当前来源及搜索关键词对应的完整结果指纹判断，其他 App 或关键词范围外的变化不误报、不阻断分页，正文仍按当前会话单独判断，具体规格见 [界面设计](docs/ui-design.md)。

Electron + React + TypeScript 独立三栏工作台，复用本项目已有浅／深主题、品牌图标、Lucide、ScrollArea mask、Tooltip、连续圆角和可调宽侧栏。不依赖 NewMax 运行时。常规弹窗标题统一使用无装饰图标的 `DsDialogHeader`，关闭按钮由 `DsDialogClose` 统一规格；搜索框的功能图标保留。来源连接使用本地 `DsSwitch` 的 small 尺寸，沿用 Pinekin 主题 token、受控授权状态、键盘操作及忙碌禁用反馈，不再通过多选后提交。

来源逻辑接入原有设计，不另做视觉方案：保留顶部返回／前进与侧栏开关、Logo 右侧搜索图标、左下插画、紧凑卡片和阅读区样式。点击搜索图标或按 `Cmd+K` / `Ctrl+K` 打开原搜索弹窗；来源搜索仅更新弹层内结果、计数与分页，不改变底下的列表、滚动位置或当前正文；关闭或清空搜索不触发主列表重载，点击结果才切换会话。搜索弹窗保持 660 × 500px，窗口较小时按视口收紧；结果数量、分页、加载、无结果和错误只改变内部内容，不改变弹窗尺寸，结果在内部滚动。返回／前进恢复来源与实际打开的会话，搜索词不进入浏览历史。连接管理集中在 **连接 App** 弹窗内，不新增侧栏分组、品牌标签或常驻搜索框。每个 App 固定一张卡片，以 small 开关即时连接／断开，统计与位置直接显示；不预先探测，不把首次扫描失败当作成功，失败保留原因和自定义位置入口。所有已适配 App 在同一个网格中显示，不保留国内／国际筛选，不按连接状态拆组、不跳转管理窗口。卡片不写死高度，所有行按内容最多的卡片统一等高，长内容由弹窗整体滚动；不展示未适配来源的假开关。连接弹窗移除「已有档案」，页脚只保留右侧「完成」；所有共享弹窗页脚均无顶部分割线，按钮尺寸和间距不变。已授权但待刷新、部分可读或读取失败的来源仍保留在侧栏；断开最后一个位置才移除对应 App，并将失效的当前筛选及浏览历史恢复到所有会话。保留键盘操作与初始焦点，不引入宿主运行时。档案入口保留原有导入流程。

Electron 保留 `sandbox`、`contextIsolation`、具名 preload API、IPC 参数及顶层 frame 校验；拒绝任意导航、新窗口和权限请求。内部桥仍为 `window.staithe`，来源能力位于 `window.staithe.sources`；原会话动作使用 `window.staithe.sourceActions` 和 `pinekin:source-actions-*` IPC。只接受已授权条目的 opaque ID，由主进程构造白名单协议，不暴露任意 URL 或命令执行接口。旧 `staithe:*` 接口不变。

空占位统一使用 `EmptyState` 与基于当前 app icon 松貂形象的六张线描 SVG。加载、统计、待刷新、暂停、部分可读、真正为空、搜索无结果、未选择、读取失败、格式未支持和无消息分别判断；只有完成统计才宣称来源为空。主阅读空区承载插画与单一行动，列表等小空间仅显示一句简短描述，不再叠加标题。主阅读区的大占位保留标题与一句简短场景描述：标题说明状态，描述补充原因／范围／能力，按钮表达动作，三者不互相复述；不重复展示本地读取／只读浏览等固定脚注。空占位整体弱强调：标题与描述直接使用全局 tertiary 及常规字重，全局三档文字共用主题基色（浅色黑、深色白），仅按 primary 88%／secondary 65%／tertiary 40% 的颜色 alpha 分级，不叠加元素 opacity 或空占位专用色阶，插画降低不透明度和饱和度，操作按钮统一使用 tertiary 样式；占位整体在所属空区的可用空间内水平、垂直居中，空间不足时可滚动。保留可读性与悬停／焦点反馈，不影响正常内容。原稿经生图后分格描摹为真实贝塞尔路径，支持深浅主题，运行时不加载原稿或请求生图服务。完整判定顺序、行动与资源路径见 [空占位规范](docs/empty-states.md)。

## 开发与验证

需要 Node.js 22.15+（建议与现有验收一致的 Node.js 24.22）和 npm。

```bash
npm ci
npm run dev
npm run test:coverage
npm run build
npm run test:e2e
```

测试先覆盖相关最小范围，然后 typecheck、覆盖率；IPC／桌面改动还需构建与 E2E。E2E 只使用合成数据、隔离 userData，替换文件选择框和系统剪贴板。`STAITHE_TEST_BACKGROUND=1` 使测试窗口从创建起隐藏、不聚焦；同时验证原生 show/focus 事件为空，不抢用户前台。正常主 dev 不使用测试标记。详见 [来源直读改造](docs/source-browser.md)。

## 兼容身份

- 显示名 Pinekin，包名 `@newmax-ai/pinekin`，安装身份 `ai.newmax.staithe` 保留。
- 默认 userData 沿用系统 appData 下的 `@newmax-ai/ember`，不自动搬迁。
- 开发隔离支持 `STAITHE_DATA_DIR`，兼容 `EMBER_DATA_DIR`，打包忽略二者。
- 文本包 `staithe.session` v1/v2，兼容 `ember.session` v1；深链 `newmax-staithe://session/<本地ID>`，兼容 `newmax-ember://`。开发模式不注册系统协议。
- 演示内容仅在测试夹具；旧演示档案不展示，也不自动删除。用户 ID、正文、标签不做品牌替换。
